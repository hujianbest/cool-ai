# 创建项目、组队并建立共享上下文 需求规格

- 日期: 2026-07-29
- frame: ./frame.md

## 1. 背景与问题

S-2 已有独立 Agent 库，但项目只有名称和示例任务，不知道真实工作区，也没有项目成员、共同目标或可信共享上下文。若直接进入模型群聊，Agent 会在缺少成员边界、任务事实源和来源记忆的情况下自由发挥，owner 仍需手工搬运背景。

S-3 先建立一个不依赖模型的项目共同体：绑定明确的本地工作区，选择平等 Agent 入组，由 owner 建立使命、子任务与带来源记忆，并能预览任一成员将读取到的相同共享上下文。

## 2. 目标与成功标准

- owner 能给项目绑定唯一、真实存在的本地目录，刷新后仍显示同一规范路径。
- owner 能选择至少两名已有 Agent 入组，项目不显示 leader/rank，成员配置刷新后仍在。
- owner 能建立一个使命和带依赖的手工子任务，并通过确定性状态规则维护看板。
- owner 能创建目标、决策、事实、产物四类带来源记忆。
- owner 选择任一成员预览上下文时，所有成员看到同一共享使命、看板、记忆与平等名册，且上下文不含 provider 密钥。

## 3. 范围

### 范围内
- 为现有项目绑定、确认改绑和显示本地工作区。
- 从 Agent 库添加/移除项目成员，保证至少两名和平等关系。
- 创建/编辑一个当前使命，创建/编辑子任务、依赖、负责人和状态。
- 创建带类型、正文、来源类型、来源引用和创建者的共享记忆；允许以新条目 supersede 旧条目。
- 生成按成员可预览的项目上下文快照。
- 项目驾驶舱的成员、看板、记忆、上下文 UI 及 loading/empty/error/disabled/success/focus。
- schema 迁移、持久化、并发冲突与路径边界测试。

### 范围外
- Agent 或模型自动发言、拆任务、领取、交棒或写记忆；S-4。
- 读取/枚举工作区文件、写文件或运行命令；S-5。
- 多使命历史、跨项目共享成员/记忆、项目模板或导入导出。
- 删除使命/记忆的物理记录；共享知识通过 supersede 保留审计链。
- 真人多人账号、远程工作区、网络文件系统专门适配。

## 4. 功能需求

### FR-1: 绑定唯一的本地工作区
- 优先级: 必须
- 描述: owner 能为项目选择本机目录，系统验证并保存其真实规范路径。
- 验收标准:
  - Given 输入是本机已存在且可读取的绝对目录 When owner 保存 Then 项目显示规范路径，刷新和应用重启后仍相同。
  - Given 输入是相对路径、不存在路径、普通文件或不可读取目录 When 保存 Then UI 显示具体简体中文错误且项目绑定不变。
  - Given 两种输入经符号链接、junction、大小写或 `..` 解析到同一物理目录 When 第二个项目尝试绑定 Then 系统识别冲突并阻止保存。
  - Given 项目已经绑定 When owner 选择不同目录 Then 必须明确确认改绑；取消确认时原绑定不变。
  - Given 工作区绑定完成 When S-3 运行 Then UI/API 只展示路径与校验状态，不读取、枚举或修改目录内容。

### FR-2: 组建平等项目组
- 优先级: 必须
- 描述: owner 能从 Agent 库为项目选择成员，项目组至少两名且没有 leader/rank。
- 验收标准:
  - Given Agent 库至少两名 When owner 选择不同 Agent 并保存 Then 成员名册显示每名 Agent 的头像、名称、职责、模型、技能与工具权限，不显示 leader/rank。
  - Given owner 尝试保存少于两名、重复 Agent 或不存在 Agent id When 保存 Then UI 显示成员错误且原名册不变。
  - Given 名册已保存 When owner 添加或移除成员并保留至少两名 Then 更新成功且刷新后仍在。
  - Given Agent 后续在 Team 中更换 model When 项目名册重新加载 Then 成员身份 id 保持不变并显示最新公开配置。

### FR-3: 建立使命与确定性看板
- 优先级: 必须
- 描述: owner 能为项目创建当前使命，手工建立有负责人、依赖和状态的子任务。
- 验收标准:
  - Given 项目已组队 When owner 输入 1–80 字符标题和 1–5000 字符目标并保存 Then 当前使命出现在项目驾驶舱，刷新后仍在。
  - Given 当前使命存在 When owner 创建 1–160 字符标题、最多 5000 字符说明的子任务 Then 子任务进入“待办”，可选负责人必须是当前成员。
  - Given 两个同使命子任务 When owner 添加前置依赖 Then 看板显示依赖；自依赖、跨使命依赖、重复依赖或形成环路时保存被拒绝。
  - Given 子任务存在 When owner 更新状态 Then 只允许待办→进行中/阻塞、进行中→阻塞/完成、阻塞→待办/进行中、完成→进行中；同状态或其他转换被拒绝，陈旧版本更新返回冲突且不覆盖新状态。
  - Given 子任务有任一未完成直接前置任务 When owner 尝试将其改为进行中或完成 Then 更新被拒绝；待办或阻塞允许保留。
  - Given 已完成任务有进行中或已完成的后继任务 When owner 尝试把该前置任务重新打开为进行中 Then 更新被拒绝，避免后继建立在未完成依赖上。
  - Given 子任务已经进行中或完成 When owner 为其新增未完成依赖 Then 保存被拒绝；只有全部新增依赖已完成时允许。
  - Given owner 尝试把任务负责人设为已移出成员 When 保存名册或任务 Then 系统要求先重新分配或清空负责人，不产生悬空引用。

### FR-4: 创建带来源的共享记忆
- 优先级: 必须
- 描述: owner 能创建目标、决策、事实、产物四类共享记忆，每条都有来源和审计信息。
- 验收标准:
  - Given 项目存在 When owner 选择类型、填写 1–20000 字符正文、来源类型和 1–2048 字符来源引用并保存 Then 记忆显示类型、正文、来源、创建者 owner 与时间，刷新后仍在。
  - Given 缺少类型、正文、来源或超出边界 When 保存 Then UI 指出具体字段且不持久化。
  - Given 来源类型是产物路径 When 来源引用是绝对路径、含 drive/UNC 前缀、NUL 或按路径段规范化后仍含 `..` When 保存 Then 系统拒绝；其他工作区相对字符串可保存为“未验证引用”，无论目标当前是否存在或是否经过符号链接/junction，S-3 都不读取/解析其文件系统目标，S-5 使用前必须重新做真实边界检查。
  - Given 旧 active 记忆不再准确 When owner 创建同项目、同类型新条目并选择 supersede 该旧条目 Then 事务把旧条目标为 inactive、链接到新条目并让新条目 active；默认上下文只包含 active 条目，旧条目不删除。
  - Given supersede 目标属于其他项目/类型、已 inactive、与新条目相同或在保存前已被其他条目 supersede When 保存 Then 整个写入被拒绝；每个新条目最多 supersede 一个 active 条目，因此不会形成分叉或环路。

### FR-5: 预览成员共享上下文
- 优先级: 必须
- 描述: owner 能选择任一项目成员，查看该成员下一阶段会收到的项目上下文快照。
- 验收标准:
  - Given 项目已有工作区、成员、使命、看板和记忆 When owner 选择任一成员预览 Then 快照包含项目 id/name、工作区显示路径、平等名册、当前使命、任务、依赖、active 记忆及每条来源。
  - Given 快照包含集合 When 序列化 Then 名册按 joinedAt/id、任务按 createdAt/id、每个任务的依赖按前置任务 createdAt/id、active 记忆按 createdAt/id、成员技能按 Agent 配置顺序/id 稳定排序。
  - Given owner 依次选择两名成员 When 比较快照 Then `shared` 深度相等；shared 名册包含全员公开 id/name/role/avatar/model、技能名称与权限摘要且不含 leader/rank，`currentAgent` 仅包含所选成员自身的 system prompt、技能指令与权限。平等指共享上下文可见性和无组织层级，不表示各成员能力/权限相同。
  - Given Provider 配置与凭据存在 When 生成/读取快照 Then JSON key（大小写不敏感）中 `apiKey/cipher/iv/tag/keyId/validationToken/masterKey/authorization` 类字段出现 0 次，provider base URL/headers 不进入快照，已知测试密钥/token/Authorization 值在序列化 JSON 中匹配 0 次。
  - Given 项目缺少工作区、少于两名成员或没有使命 When 预览 Then UI 明确列出缺失前置条件，不伪造空上下文为“已就绪”。

### FR-6: 项目上下文状态完整
- 优先级: 必须
- 描述: 成员、使命、看板、记忆和上下文区域分别提供 loading、empty、error 与恢复动作。
- 验收标准:
  - Given 数据尚未返回 When 打开项目 Then 各区域显示 loading 而非提前 empty。
  - Given 某区域无数据 When 加载完成 Then 显示对应下一步动作，顺序引导为工作区→成员→使命→任务/记忆。
  - Given 加载或保存失败 When 显示 error Then owner 可重试且未提交草稿不清空。
  - Given 保存成功 When UI 更新 Then 焦点移到新实体标题并以 `aria-live=polite` 宣告。

## 5. 非功能需求

### NFR-1: 工作区路径安全
- 要求: S-3 对工作区目录内容执行读取、枚举、写入和命令调用的次数均为 0；同一物理目录只能存在 1 个 active 项目绑定；应用日志和错误响应不包含测试工作区的完整路径。
- 出处: product/assumptions.md A-27、A-28 与 frame 风险档位 3
- 验证方式: 以真实临时目录、别名路径和两个项目执行黑盒绑定；核对操作审计中内容读取/枚举/写入/命令均为 0、第二个 active 绑定被拒绝、错误响应与捕获日志不含完整测试路径。

### NFR-2: 上下文完整性
- 要求: 对同一数据库版本连续生成两次快照时 JSON 深度相等；不同成员的 shared 部分深度相等；非法依赖环路、悬空成员/技能/负责人和陈旧版本成功写入次数为 0。
- 出处: product/assumptions.md A-10、A-29 至 A-34
- 验证方式: 对合法/非法依赖、悬空引用与陈旧版本执行外部请求，核对写入结果；重复读取并比较规范 JSON，扫描快照中的禁用字段类别与测试凭据值。

### NFR-3: 可访问性
- 要求: 新增交互满足 WCAG AA、目标至少 44×44px、看板与表单键盘可完成、状态/依赖/成员不只依赖颜色表达、字段错误语义关联且焦点可见。
- 出处: product/product.md 与 ext-ui-design
- 验证方式: 仅使用键盘完成桌面与窄屏主路径，核对语义树、焦点、文本状态、目标尺寸、对比度与真实渲染截图。

## 6. 约束与依赖

- 复用 S-1 项目与任务数据、S-2 Agent/Skill/Provider 身份；迁移不得丢失既有数据。
- 工作区只允许本机目录；不支持 URL、远程挂载协议或浏览器上传目录。
- S-3 没有 Agent 执行，因此“成员可读取”通过相同上下文快照 API 与 UI 预览验收。
- owner 是 S-3 记忆唯一写入者，来源创建者固定为 owner；Agent 写入从 S-4 开始。

## 7. 假设

- A-27/A-28: 真实规范目录、唯一绑定、改绑确认；若同目录多项目被允许，将改变后续工具隔离。
- A-29/A-32: 至少两名且无 leader/rank；若单 Agent 项目成为需求，需调整组队与上下文就绪条件。
- A-30: owner 手工看板；若改为自动拆解，本规格需增加 Agent 运行、授权和失败恢复并升到 S-4 范围。
- A-31: 四类显式来源记忆；若聊天可自动入库，本规格需新增提取、来源可信度和 owner 撤销规则。
- A-33: 当前文本边界；若推翻，FR-3/FR-4 的字段验收与上下文容量测试必须同步修改。
- A-34: 固定状态与无环依赖；若增加状态或允许环路，FR-3 的全部转换、依赖和快照语义必须重定格。
