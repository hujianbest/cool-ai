# 项目内持久线程与上下文续接需求规格

- 日期: 2026-08-08
- frame: ./frame.md

## 1. 背景与问题

Cool AI 当前把公开消息按项目汇总，并只突出最近一次协作运行；owner 无法在同一项目内分开组织多个长期话题，也无法明确选择某段公开上下文继续。S-12 在不改变公开协作、owner 裁决和独立复核边界的前提下建立项目内持久线程。

## 2. 目标与成功标准

- owner 能在一个项目创建至少两个线程，在列表中切换并向选定线程继续发言。
- 重新启动应用后，线程归属、公开消息顺序、成员策略、run 来源和当前可继续状态与重启前一致。
- 任一线程/API/页面都不能显示或写入其他项目的线程数据。
- 已有项目升级后原公开消息与运行仍可访问和续接。

## 3. 范围

### 范围内
- 项目内线程创建、列表、选择、深链与续接。
- 每线程公开消息上下文、成员策略和 CollaborationRun 来源。
- 重启恢复、遗留协作数据兼容、项目隔离、凭据拒绝和公开线程审计。

### 范围外
- 结构化消息卡、对话分支、回复引用、草稿、附件、搜索、标签、收藏、回收站、消息队列、Steer、分屏、跨线程引用及消息删除；均由后续切片处理。
- 私语、Agent 投票和自动并行多线程运行；与 D-20 或既有生命周期边界冲突。

## 4. 功能需求

### FR-1: 创建并导航项目线程
- 优先级: 必须
- 描述: owner 可用 1–80 字符标题在当前项目创建线程；显式创建允许同名线程，稳定身份而非标题决定选中项。线程按最近公开活动的确定顺序排列。
- 验收标准:
  - Given 项目可用 When owner 创建两个不同标题的线程并分别发言 Then 列表显示两个稳定条目，最近发言线程在前，选择项与消息表面一致。
  - Given 标题为空、超过 80 字符、线程列表 loading/error 或创建结果不确定 When owner 操作 Then 界面分别显示禁用/明确错误/重试或先读取事实对账后的唯一结果，不出现伪造或重复线程。
  - Given 项目还没有线程 When owner 打开协作表面 Then 空状态只提供创建线程的明确 CTA，不把无归属消息 composer 显示为可提交。
  - Given owner 两次显式创建同名线程 When 均成功 Then 显示两个可分别选择的稳定条目；Given 同一次创建操作因超时重试 When 对账 Then 只存在一个线程。
  - Given 线程创建、成员策略变化、接受 owner/Agent 公开消息或产生公开 run 事件 When 重新读取列表 Then 该事实更新线程最近活动；只有创建事实的线程按创建活动排序，并发后重复读取与重启保持同一确定顺序。

### FR-2: 只续接当前线程公开上下文
- 优先级: 必须
- 描述: owner 与 Agent 在当前线程看到并续接该线程的公开消息；项目 Mission、看板和 active 记忆仍是共享事实。
- 验收标准:
  - Given 同项目线程 A、B 各有不同消息 When 在 A 继续 Agent 协作 Then Agent 可见聊天历史只来自 A，B 的消息不进入其输入或 UI，项目共享事实仍可见。
  - Given 切换线程或项目 When composer、mention、成员缓存、轮询或延迟响应仍持有旧状态 Then 旧状态立即清空或失效，不得闪现、提交、覆盖或合并到新目标。

### FR-3: 保持并修复线程成员策略
- 优先级: 必须
- 描述: 创建线程时 owner 显式选择当前项目成员；策略只因 owner 的显式修改而变化，并保留历史作者显示。
- 验收标准:
  - Given 线程已有成员策略 When 项目新增成员或 Agent 改名 Then 新成员不自动加入，历史消息作者仍显示发送时名称，当前策略可辨认。
  - Given 策略成员已移出项目 When owner 打开或续接线程 Then 历史仍可读，Agent 续接被阻止并说明需修复；修复后只允许当前项目有效成员。
  - Given 桌面或窄屏打开线程 When 查看其上下文 Then 当前成员策略、不可用成员和修复入口可被 owner 看见且不会与项目 live roster 混淆。
  - Given owner 用当前策略版本提交另一组至少两名有效项目成员 When 无冲突 Then 新策略生效并留下公开事实；空集合、重复、其他项目或不可用成员均被拒绝且旧策略不变。
  - Given 两个页面基于同一旧策略并发修改 When 后一请求提交 Then 得到陈旧冲突并重读事实，不覆盖较新策略。
  - Given Agent 公开输出提议成员变化 When 被接收 Then 只作为消息显示，不被解释为策略写入；策略只由 owner 的显式控件修改。

### FR-4: 保持运行生命周期和来源
- 优先级: 必须
- 描述: 每次 CollaborationRun 归属一个线程；切换线程不隐式暂停、终止、迁移或重放运行。
- 验收标准:
  - Given 线程 A 有非终态运行 When 切到线程 B Then A 状态不变，B 可接收 owner 公开消息，但启动 Agent 续接被阻止并提供返回 A 的入口。
  - Given 项目无其他非终态运行 When 在历史线程继续 Then 新运行归属该线程，历史 run、review 和 delivery 来源仍指向原身份。
  - Given 当前线程包含多个历史 run When 打开运行、执行、复核或交付表面 Then 只使用当前线程明确选中的适用 run，不以“项目最新 run”静默替代。
  - Given 从运行 Continue/Retry 或从终态线程开始新一轮协作 When owner 操作 Then 前者只恢复同一 run，后者创建归属同一线程的新 run，两种“续接”在界面与审计中可区分。

### FR-5: 重启与深链恢复
- 优先级: 必须
- 描述: 线程事实持久化；线程深链优先选择目标，无深链时选择项目最近公开活动的可用线程。
- 验收标准:
  - Given 多线程项目 When 关闭并重启应用后打开同一线程深链 Then 线程、消息、成员策略和运行状态与重启前一致。
  - Given 重启时有中断或过期调用 When 页面恢复 Then 只展示经事实对账后的状态，不自动重发外部调用。
  - Given 深链线程不存在或不属于当前项目 When 打开 Then 不泄漏其存在或内容，并回到明确的项目线程错误/可选状态。
  - Given owner 从线程进入设置再返回或使用浏览器前进/后退 When 导航完成 Then 项目与线程深链保持，焦点和选中状态对应 URL；无有效线程参数时才使用最近公开活动线程。

### FR-6: 强制项目隔离
- 优先级: 必须
- 描述: 所有线程、消息、成员策略、运行和事件读写都必须同时服从其项目归属。
- 验收标准:
  - Given 项目 A、B 各有线程 When 使用 A 的项目上下文访问或修改 B 的任一线程资源 Then 请求失败关闭，A/B 均不发生写入且响应不包含 B 内容。
  - Given 客户端快速切换项目 When 旧项目请求延迟返回 Then 旧响应不得覆盖新项目线程列表、当前选择或 composer 目标。
  - Given 仅持有其他项目的 run/message/event 标识 When 通过任一详情或动作入口访问 Then 与未知资源得到相同的安全失败，不可借响应推断归属。

### FR-7: 阻止可识别凭据进入消息
- 优先级: 必须
- 描述: owner 初始目标、owner 后续消息和 Agent 公开输出均拒绝以下可枚举类别：本机已配置 Provider 密钥明文、PEM 私钥块、Authorization Basic/Bearer 值，以及 api-key/token/secret/password 已知字段后的非占位值；`***`、`<redacted>`、`${ENV_NAME}` 和仅字段名的代码示例不拒绝。
- 验收标准:
  - Given 上述三个入口的消息分别含任一拒绝类别 When 提交 Then 消息、事件、日志、API 响应和 DOM 均不含原值，线程序列不产生业务消息，界面只显示通用修正提示。
  - Given 消息只含明确占位符、环境变量引用、字段名示例或不匹配类别的普通代码/自然语言 When 提交 Then 不因凭据规则被拒绝；系统不宣称识别所有秘密。

### FR-8: 兼容既有公开协作历史
- 优先级: 必须
- 描述: 升级后每个既有项目的公开消息和 CollaborationRun 都归入一个默认线程，保留原顺序和来源且可继续。
- 验收标准:
  - Given 含 project-only 消息、终态/非终态运行和下游来源的升级前数据 When 首次升级并重复启动 Then 只形成一个默认线程，初始策略为迁移时仍有效的完整项目成员集合，所有原事实可读且不重复迁移。
  - Given 历史作者已离开项目 When 默认线程形成 Then 作者名称快照仍可读但该身份不加入策略；Given 有效成员不足两名或引用不可用 Then 线程只读并要求 owner 修复后才允许 Agent 续接。
  - Given 升级数据违反项目归属或顺序不变量 When 启动 Then 迁移失败关闭，不静默丢弃、改写或跨项目归并。
  - Given 升级后的默认线程含多个历史 run When onboarding、执行、复核和交付读取公开事实 Then 严格解析仍成功且不会把不同 run 的合法消息误判为损坏数据。

### FR-9: 提供可追溯公开线程事件
- 优先级: 必须
- 描述: 线程创建、成员策略变化、owner/Agent 公开消息、运行关联及公开 run 事件均留下按线程有序且可公开查看的事实。
- 验收标准:
  - Given 创建线程、修复成员策略、owner 与 Agent 分别发言并开始运行 When 读取线程历史 Then 每项事实只出现一次、顺序稳定，并可辨认 actor、目标线程和关联 run。
  - Given 重试、并发或进程重启 When 相同操作再次到达 Then 不产生重复业务事实，冲突得到明确结果。

## 5. 非功能需求

### NFR-1: 可访问与响应式交互
- 要求: 创建、列表、选择、错误恢复和返回活动线程均可用键盘完成，焦点可见，触控目标至少 44×44px，文本对比度和语义满足基础 WCAG AA；桌面与既有窄屏布局均无本切片内容遮挡。
- 出处: `product/product.md` MVP 边界、`product/architecture.md` 横切约定、A-7、A-17。
- 验证方式: 在本切片受影响表面验证键盘、焦点、对比度、语义以及桌面/窄屏布局；不得以未受影响页面问题冒充本切片通过或失败。

### NFR-2: 持久事实完整性
- 要求: 重启、迁移重跑、重复操作和并发写入后，项目归属、线程顺序、消息顺序、策略和 run 来源均唯一且一致；发现不变量破坏时失败关闭。
- 出处: S-12 演示判据、`product/architecture.md` 写入与失败关闭约定。
- 验证方式: 用升级前数据、并发/重复操作和真实进程重启分别核对持久事实与可见结果。

## 6. 约束与依赖

- 依赖已交付 S-9；沿用既有本地单 owner Web 产品、持久事实兼容要求和协作安全边界。
- 保持公开轨迹、平等 Agent、owner 决策与独立复核；不得保存隐藏思维链或原始 Provider 响应。
- 同项目最多一个非终态 CollaborationRun；verified-handle、sandbox 和审批不适用于纯线程组织。
- 不复制 Clowder 品牌、源码、角色、文案或资产。
