# 协作与接力

Cool AI 的协作由项目群聊、持棒者、结构化动作、任务看板和时间线共同组成。平台负责校验与调度，不充当隐藏的“总管 Agent”。

## 发起与观察协作

1. 完成 Provider、至少两个 Agent、项目成员和使命配置。
2. 在项目群聊提交具体目标。
3. Agent 通过真实 Provider 调用生成公开消息，并提交任务提案、领取、交棒、决策请求或完成提议。
4. 在时间线查看当前持棒者、模型调用状态、公开动作、usage、业务轮次和错误。

每轮只允许一个 Agent 提交协作动作；独立任务的并行发生在后续 execution 层。模型输出必须是严格 JSON object；格式错误最多触发一次修复调用。Provider 必须报告可验证的非负整数 usage，且 `total_tokens` 等于 prompt 与 completion 之和，否则该轮失败并暂停，不伪造用量。

## owner 如何介入

- 直接发言：新消息优先于后续自动推进。
- `@Agent`：把下一棒定向给指定项目成员。
- 回答决策：选择 2–8 个选项之一或提交自由文本，运行再继续。
- 暂停：阻止新轮次；已在途的模型结果不会越过暂停提交业务动作。
- 继续或重试：由 owner 显式触发，不会因刷新或重启自动重放外部调用。
- 停止：终结当前协作运行，不能再继续。

## 接力与边界

- 交棒必须指定另一名成员并给出摘要和原因。
- 单次协作运行最多 50 个已提交业务轮次；每个 Agent 还受自身 token 和最大交棒数约束。
- 模型 HTTP 调用 90 秒超时，持久 attempt lease 为 120 秒。lease 过期或应用中断后，旧结果不能提交，owner 需显式重试。
- 浏览器驱动推进，没有常驻后台 worker；关闭页面会停止自动推进，但持久状态仍可在重新打开后读取。
- 聊天和时间线保存公开消息与结构化事件，不保存或展示模型隐藏思维链。
