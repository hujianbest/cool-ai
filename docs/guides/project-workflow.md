# 项目工作流

项目把本地工作区、平等 Agent 成员、使命、任务 DAG、协作历史和共享记忆放在同一上下文中。使命看板是任务负责人、依赖与状态的机器事实源，不能只靠聊天文本宣告完成。

## 1. 创建项目并绑定工作区

1. 创建项目。
2. 选择本机已存在、可读取的绝对目录作为工作区。
3. 核对规范化后的路径；同一规范工作区同一时间只能绑定一个项目。

绑定本身不等于允许任意文件访问。实际 execution 仍受 Agent 权限、支持平台、sandbox、审批和合并规则约束。

## 2. 添加项目成员

选择至少两个已配置 Agent 加入项目。成员之间没有 leader/rank；职责和工具权限来自 Agent 配置，不代表固定上下级。同一 Agent 在一个项目中只能出现一次。

## 3. 建立使命和 DAG

为使命写清标题与目标，再添加工作项：

- 每项包含标题、说明、负责人和状态；
- 依赖必须属于同一使命；
- 禁止自依赖和环；
- 只有依赖满足、已领取并进入进行中的任务才能进入安全执行；
- 看板状态变更带版本冲突保护，旧页面提交可能被拒绝，需要刷新后重试。

任务状态为待办、进行中、阻塞或完成。进入 S-6 复核闭环后，界面还会区分执行中、待复核、复核中、待返工、待 owner 和已通过完成。只有当前结果通过独立复核，任务才满足完成门槛。

## 4. 运行完整闭环

1. 在群聊提交边界明确的目标，让 Agent 提议、领取并交棒。
2. owner 处理 @Agent、决策请求、暂停或方向变更。
3. 对 DAG-ready 任务启动隔离 execution，检查验证与 staged 变更。
4. 通过审批边界后合并；冲突、stale、删除、二进制或超限变更不会静默自动合入。
5. 为结果选择非执行者 Agent 复核；按退回、升级或通过处理。
6. 查看复核 Agent 提议并由通过裁决确认的记忆，以及 owner 直接维护的目标等记忆。
7. 所有任务通过后生成最终交付。使命只有在统一完成门槛满足且交付持久化后才会完成。

协作细节见[协作与接力](./collaboration.md)，执行细节见[安全执行](./safe-execution.md)，复核细节见[复核与交付](./review-and-delivery.md)。
