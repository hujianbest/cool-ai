# 采用领域模块化单体与受控扩展端口

- 状态: accepted
- 日期: 2026-08-09

## 背景

Cool AI 已形成单 owner、平等角色 Agent、公开协作、受限工作区执行、独立复核和可追溯交付的本地产品闭环。后续范围还包括 Mission 治理、知识生命周期、运行洞察、证据回放以及外部运行时。现有按技术层罗列文件的架构地图不足以约束事实所有权、跨域写入和扩展安全；继续按页面或数据库表临时拼接，会产生多写入口、隐式耦合和无法机械验证的安全旁路。

本决定面向一个本地优先、单进程、同一 SQLite 强事务边界的产品。它既要允许按可演示结果持续扩展，又必须保留 Project/Thread/Run tuple、冻结来源、operation/version/lease、verified-handle、sandbox、审批和独立复核等已交付约束。

## 驱动因素

- 一个业务事实只能有一个逻辑 owner，不能由多个页面、路由或服务直接改写。
- 涉及多个领域的用户结果需要原子协调，但不应把领域规则集中到万能服务。
- 新 Provider、CLI、MCP 或其他外部能力应可替换，同时不能获得绕过安全协议的进程内权限。
- 读模型和运维视图需要低耦合扩展，但不能反向成为命令事实源。
- 本地产品需要保留 SQLite 事务、一体化部署和简单恢复，不为组织规模预付分布式复杂度。
- 交付单位必须是可演示的垂直切片，而架构边界必须长期稳定并可机械检查。

## 候选方案

### 候选 A：领域模块化单体

按事实所有权划分逻辑子系统，每个子系统通过公开 Interface 提供命令与查询；跨子系统行为由 Application Workflow 协调，并在同一 SQLite 事务中维护强不变量。

优点是符合当前单机部署和事务模型，能逐步收敛多写入口；缺点是模块隔离主要依赖代码结构、所有权清单和机械检查，若缺少约束容易退化成普通分层单体。

### 候选 B：垂直切片优先

围绕每个可演示用户结果组织 UI、API、领域与持久化代码，让一项能力独立交付，不先建立长期水平层次。

优点是反馈快、交付边界清晰；缺点是单独采用时容易让每个切片各建写路径、重复安全规则和事实定义，长期形成以页面为边界的碎片化系统。

### 候选 C：事件驱动与选择性事件溯源

以领域事件连接能力，重要聚合通过事件历史重建状态，查询由事件投影产生。

优点是历史、回放和投影天然清晰；缺点是全面事件溯源会把现有状态模型、迁移、版本链和恢复协议整体改写，并引入当前产品不需要的最终一致性与事件演进成本。对少量公开事件和 outbox 有价值，对所有事实并不合适。

### 候选 D：微内核与扩展宿主

以稳定核心和通用进程内插件 API 承载 Provider、工具、UI 或业务扩展。

优点是扩展种类多、第三方接入灵活；缺点是在可信本机进程内，通用插件可直接接触文件、凭据、数据库和网络，难以证明最小权限、隔离、审批与可撤销性。插件兼容层也会过早冻结尚未稳定的领域模型。

## 决定

选择混合方案：

1. 主体采用**领域模块化单体**。逻辑子系统拥有明确事实，并只通过公开 Interface 访问其他子系统。
2. 跨域用户结果由**Application Workflow** 协调；需要强一致时复用同一 SQLite 事务，不通过页面回调或事件链拼接关键写入。
3. 产品按**垂直切片**交付；切片穿过必要层次，但不得绕过事实 owner 或复制安全协议。
4. 仅对跨域通知、运维查询、回放和可重建读模型采用**同库 outbox 与选择性公开事件投影**。命令状态继续由所属子系统的当前事实和不可变版本链决定。
5. 外部能力通过**受控扩展端口**接入。只有存在真实替换需求或信任边界时才建立 Interface；Adapter 必须服从能力声明、最小权限、verified-handle、sandbox、审批、脱敏、审计和生命周期控制。

明确拒绝当前微服务化、全面事件溯源和通用进程内插件：

- 不拆微服务：当前没有独立部署、独立扩缩容或组织自治需求；拆分会破坏 SQLite 原子不变量并增加网络失败模式。
- 不做全面事件溯源：现有版本化事实、迁移和恢复协议已经提供所需审计；事件仅用于明确的投影与集成接缝。
- 不开放通用进程内插件：扩展不是安全协议的免审通行证；任意插件不得以“已安装”为由直接获得数据库、宿主文件、凭据、进程或网络访问。

## 后果

正向后果：

- 每张可写表和每类命令事实都能登记唯一 owner，跨域写入可追踪到明确 Workflow。
- SQLite 继续承担本地强事务与恢复边界，部署和备份模型保持简单。
- UI、HTTP、数据库、Windows 工作区、Provider、CLI 和 MCP 都可作为 Adapter 演进，不侵入领域事实。
- 新读视图可从公开事件重建，不必让报表或运维页面获得命令写权。
- 垂直切片仍能快速交付，同时共享稳定的能力 Interface 与安全协议。

代价与约束：

- 需要维护子系统/写表 owner 清单、公开 Interface 和允许的依赖方向，并用机械检查阻止回退。
- Application Workflow 必须保持薄，只协调步骤、事务和补偿，不吸收各子系统规则。
- 选择性事件需要 schema、幂等消费、outbox 原子写入和可重建投影纪律。
- 旧代码会在迁移期同时存在目标边界与历史技术层，必须按写入口优先的顺序渐进收敛，不能一次性重写。
- 受控 Adapter 比通用插件扩展速度慢，但换来可验证的信任边界和可撤销权限。

## 重新评估触发条件

出现以下事实之一时重新评估，但不自动改变本决定：

- 某子系统出现独立部署、独立扩缩容、故障隔离或不同数据驻留的真实需求，且收益足以承担分布式一致性成本。
- SQLite 单机写入、备份或恢复经测量成为无法通过单体内优化解决的瓶颈。
- 某类事实必须按历史事件任意时点重建、分叉或接受监管级事件账本，而现有版本链与审计无法满足。
- 第三方扩展形成稳定、可信且可版本化的生态需求，并具备进程外隔离、签名、权限、撤销和兼容测试基础。
- 跨域 Workflow 数量或耦合度持续上升，表明子系统边界或事实所有权划分错误。
- 真实替换实现达到两个以上且稳定，证明新的 Interface 具有价值；在此之前不为假想扩展抽象。
