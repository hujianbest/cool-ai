# 产品定义

- 日期: 2026-08-08（按 010 最终 owner 决定更新边界）
- 想法一句话: 为独立产品创造者提供一个本地优先的 Web 多 Agent 协作平台，让 owner 把可配置的角色 Agent 组成平等项目组，交给它们一个产品目标后自主讨论、接力执行并交付可审计成果。
- 目标用户: 独自推动一个真实产品从想法走向交付、会配置 OpenAI-compatible 模型服务，但不想亲自充当调研、设计、开发与复核 Agent 之间“路由器”的独立产品创造者。
- 要解决的问题: 现有多模型协作依赖 owner 手工复制上下文、分派下一棒、汇总分散的文档/设计/代码成果并追踪验证结果；角色身份、协作历史和安全边界也容易随会话丢失。
- 成功标准: owner 能在 Web UI 中配置模型服务、技能与至少两个角色 Agent，创建并绑定一个本地产品项目工作区后组建项目组；owner 在群聊提交一个边界明确的产品目标，Agent 将其拆到使命看板，按依赖自主接力或并行处理，并通过结构化共享记忆同步目标、事实、决策与产物；团队在受限工作区内产出并验证文档、设计或代码成果，经同伴复核后给出最终报告；owner 全程可发言或 @Agent、回答决策请求、查看轨迹、暂停运行并审批高风险动作。
- 用户确认: auto-approved 2026-07-29（连续开发模式）

## MVP 边界（做什么）

- 本地单 owner Web 应用；项目、角色、会话、执行事件和结果持久化。
- 可配置 OpenAI-compatible 服务（base URL、API key、model），并可验证连接。
- 可配置角色 Agent（名称、职责、系统提示、模型、技能、能力与工具权限），提供可编辑的入门模板但不设固定领导角色。
- 主工作区采用“协作驾驶舱”信息架构：左侧项目与使命导航，中间群聊和协作事件流，右侧按当前上下文展示使命看板、共享记忆或审批。
- 视觉采用温暖、有角色感但不幼稚的团队空间；每名 Agent 有稳定、可辨识的头像与强调色，整体视觉不复制 Clowder AI 的猫角色或品牌。
- 创建项目、绑定本地工作区、从 Agent 库组建平等项目组，并给项目组提交目标。
- owner 与 Agent 共处一个项目群聊；owner 可随时发言、@指定 Agent、回答决策请求或改变方向。
- 使命看板把目标拆成有负责人、依赖和状态的子任务，并显示当前接力棒；owner 和 Agent 都能更新。
- 项目群组中的真实多 Agent 对话、明确交棒、自主接力与独立子任务并行处理；平台只负责调度、安全与审计，不充当隐藏的“总管 Agent”。
- 结构化共享记忆保存项目目标、已确认决策、可引用事实、产物索引与复盘经验，所有组员在后续回合中可读取。
- 受限工作区工具：读取/修改项目中的文档、设计资产与代码，按任务需要运行验证命令；越界、破坏性或外部发布动作必须暂停并等待 owner 审批。
- 可观察的运行状态：当前持棒者、消息与工具事件、文件改动、验证结果、预算/轮次边界、暂停/继续/终止。
- 完成闭环：另一名 Agent 复核结果，项目组形成最终摘要、改动与验证证据，历史可在重启后继续查看。
- 所有关键交互覆盖 loading / empty / error，视觉值统一走 design token；文本对比度、键盘操作和焦点状态满足基础 WCAG AA 要求。

## 已确认扩展范围

- 010 的 72 项最终决定汇总为：继承 42、已有保持 11、延后 9、不继承 10；以下按能力域表达产品边界。
- 应用外壳与设置：保持现有驾驶舱与设计 token，并扩展统一设置导航/检索、亮暗主题和渐进式首次使用引导。
- 聊天与 Agent 协作：扩展持久线程、搜索/标签/收藏/回收站、结构化消息、队列与 steer、图片附件、回复引用、草稿恢复；继续公开协作，不引入私语或 Agent 投票。
- 项目与安全执行：扩展绑定工作区内的只读浏览、受控编辑/Git、终端/浏览器预览、外部运行会话和统一审计；所有动作仍走 verified-handle、sandbox、审批、冲突检测与审计。
- Mission 与治理：在现有使命看板上扩展统一审批、依赖全景、可审计 SOP 状态和租约控制，不建立与产品 backlog 并行的第二事实源。
- 记忆与知识：扩展项目内检索、知识动态、索引健康、目录/集合、来源可追溯图谱和由真实 Agent 署名的提炼发布。
- Provider、Skill、设置与运维：保持 OpenAI-compatible Provider、本地 Skill 与 Agent 配置，并纳入原生 Agent CLI/ACP、受控 MCP、已安装插件、能力市场、语音、可观察性、用量/配额和救援运维。此前对 CLI Provider、MCP、插件、市场与语音的 MVP 排除由本次 owner 决定取代；每项须独立切片，所有外部执行、供应链和凭据仍受 sandbox、最小权限、审批、脱敏与审计边界。
- 通知与外部集成：只扩展浏览器通知/PWA；不继承外部 IM/连接器、Signals/协作研读/播客、外部社区发布或无人值守自动化。
- 导出与回放：扩展脱敏数据导出、可审计运行轨迹和本地只读回放；保持现有交付包，桌面壳/自动更新、公开分享及写入式回放等能力延后。

## 不做或延后

- 多人账号、邀请、权限与实时真人协作；首版成功后再切片。
- 飞书、Telegram 等外部 IM/连接器、Signals 资讯流及协作研读、研究播客和外部社区发布不继承。
- 游戏、主动人格助手、多目标私语和 Agent 投票不继承。
- 消息分支/跨线程分屏与来源导航、消息级删除、Need Audit、另一套 Slice/Reflux 治理、桌面安装器/自动更新、公开分享和回放注释延后。
- 完整 token 计费、配额结算和商业订阅系统；首版只保留必要的运行限额与基础用量信息。
- 云端托管、移动端和多节点分布式执行不在当前范围。
- 定时 daemon、值班简报与跨重启自动后台运行不继承。
- 无限制 shell、绕过审批的外部发布/部署、越出绑定工作区的文件操作，以及未受控的外部执行、插件或凭据访问始终排除。
- 功能范围的扩大不授权复制 Clowder AI 的名称、猫角色、商标、文案、源码或视觉资产；只重新实现已确认的用户结果与通用原则。
