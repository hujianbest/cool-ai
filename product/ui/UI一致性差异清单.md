# UI 一致性差异清单（应用 vs UCD）

- 日期: 2026-10-11
- 状态: 待修复（由主任务执行）；本清单为只读发现记录，不代表已修复
- 基准: `product/ui/UI设计.md`（UCD，唯一基准）+ `product/ui/preview-ucd.html`（高保真原型）
- 方法: 自包含审计运行器驱动真实应用（独立 dev server + 临时库 + 脚本化选夹 + mock OpenAI 兼容 Provider + 结构化回合回复），覆盖 27 个屏/交互状态与全部按钮点击后的界面；截图与逐步状态见 `tests/browser/test-artifacts/ui-audit/`（gitignored），原型参考图见 `tests/browser/test-artifacts/ucd-references/`（7 视图）。重跑：`node tests/browser/test-artifacts/ui-audit-runner.mjs`
- 严重级别: **P0** 阻断主路径 / **P1** 与 UCD 明确不符 / **P2** 文案与细节

## P0 — 阻断主路径

### U-01 首页 1:1 直聊无法发送消息（409）
- **UCD 依据**: §9.1.1 场景 3「未选项目时的 1:1 直聊（阶段 1 核心路径）」——可直接与助手对话。
- **现状**: 在首页新建个人对话后发送消息（带 `@提及` 与纯文本均试），`POST /api/projects/:id/threads/:threadId/runs` 返回 **409 `THREAD_POLICY_REPAIR_REQUIRED`**（`prompt-builder` 要求线程策略 ≥2 名成员；个人对话按 1:1 只有 1 名成员）。界面显示「无法启动协作，请稍后重试。」，草稿保留在 Composer。个人对话**完全无法发送**。
- **证据**: `ui-audit/11c-mention-send-result.png`、`ui-audit/11b-chat-reply.png`；运行日志 `API ERROR 409 ... THREAD_POLICY_REPAIR_REQUIRED`。
- **修复方向**: 为直聊线程提供单 Agent 运行路径（放宽 ≥2 策略成员约束或直聊专用运行校验）；错误文案按场景细分。

## P1 — 与 UCD 明确不符

### U-02 项目对话首条消息要求先有使命，且无引导
- **UCD 依据**: §9.1.2「用户输入 @规划 发送任务 → Agent 接力回复」为主路径；未说明需先创建使命。
- **现状**: 新项目对话发送首条消息返回 **409 `CONTEXT_NOT_READY`（`fields.mission: required`）**，界面仅提示「项目协作上下文尚未就绪。」，无任何指向「创建使命」的链接或动作；草稿保留。
- **证据**: `ui-audit/16b-project-chat-reply.png`（首轮失败态）、API 日志。
- **修复方向**: 二选一——空对话状态给出「先创建使命」明确入口（并解释原因）；或运行启动时自动确保最小上下文。错误提示补充可操作指引。

### U-03 图标轨「团队/设置」未按 UCD 收进底部分组
- **UCD 依据**: §7.1「底部分组（经分割线隔离）：6 团队 7 设置 8 主题」。
- **现状**: 团队、设置紧跟在审计图标之后停在轨道上半段（约 y=281/333），下方大片空白，仅主题（月亮）贴底；无分割线。
- **证据**: `ui-audit/` 基线截图左侧轨道裁剪（`test-artifacts/rail-full-crop.png`）；任意项目截图可见。
- **修复方向**: 将团队/设置/主题合并为贴底分组并加分割线（注意与固定设置入口的布局关系）。

### U-04 消息流系统事实以大卡片渲染，淹没对话
- **UCD 依据**: §9.1.2/§9.1.3 协作时间线以 Owner 气泡、Agent 消息与结构化卡片为主体；系统事实应为安静的次要样式（历史实现口径「系统事实安静行」）。
- **现状**: 「对话已创建 / 协作成员策略已更新 / 运行已关联 / 协作已启动 / 正在调用模型 / 模型调用已完成」等系统事实每条渲染为约 90px 高的大边框卡片，视觉重量超过 Owner 气泡，消息流被系统卡片主导。
- **证据**: `ui-audit/16b-project-chat-reply.png`、`ui-audit/22b-recycle-bin.png`、`ui-audit/23b-batch-bar.png`。
- **修复方向**: 系统事实改安静行（单行文案 + 弱化时间），仅结构化决策类事实保留卡片。

### U-05 任务看板缺使命卡片（Mission Banner）
- **UCD 依据**: §9.2.1 第 2 条「使命卡片：展示项目核心目标、验收条件与当前整体完成百分比进度条」。
- **现状**: 看板无使命 banner；使命内容只有在点击「编辑使命」后才以表单出现。已创建使命（标题+目标）后看板不展示目标与完成度。
- **证据**: `ui-audit/18b-mission-created.png`、`ui-audit/18d-board-with-card.png`。
- **修复方向**: 看板顶部加使命卡（目标 + 验收条件 + 完成度进度条）。

### U-06 任务看板顶栏缺主操作与视图切换
- **UCD 依据**: §9.2.1 第 1 条「顶栏：← 返回对话、项目名、新建任务按钮、看板/列表视图切换开关」；原型为标题居中 + 右侧「＋ 新建任务」。
- **现状**: 顶栏只有「← 返回对话」+ 左对齐标题「任务看板 · <项目>」；无「新建任务」文字按钮（新建任务退化为任务区右上角「+」图标）；无看板/列表切换。
- **证据**: `ui-audit/18d-board-with-card.png` vs 原型 `ucd-references/ucd-tasks.png`。
- **修复方向**: 顶栏补齐右侧「新建任务」主按钮；补视图切换或同步更新 UCD（二选一，先改文档再改实现）。

### U-07 任务卡片信息结构缺编号等元数据
- **UCD 依据**: §9.2.1「任务卡片：编号、标题、负责人 Agent 身份徽标、依赖前置项标签、派发租约倒计时」。
- **现状**: 卡片仅标题（无 `#N` 编号；本次条目未设负责人属数据差异，但编号为结构性缺失）；原型卡含 `#1/#2/#3` 前缀。
- **证据**: `ui-audit/18d-board-with-card.png` vs 原型。
- **修复方向**: 卡片补编号与元数据行（负责人/依赖/租约按数据出现）。

### U-08 记忆视图信息架构与 UCD §9.2.4 不一致
- **UCD 依据**: §9.2.4 线框与组件列表——顶栏「＋ 沉淀新记忆」文字按钮；「索引健康条 → 顶部搜索框 + 类型过滤胶囊（全部/目标/决策/事实/产物/经验）→ 记忆卡片列表（主内容）」；集合目录/关系列表/提炼候选为附加区块。
- **现状**: ① 无顶部搜索输入框与类型过滤胶囊，仅有「🔍」图标按钮与「＋」圆形图标；② 记忆卡片列表被排到页面底部「知识动态」区，提炼候选/知识集合/关系列表在其之上（主内容被下沉）；③ 顶栏无「＋ 沉淀新记忆」文字主按钮。
- **证据**: `ui-audit/19-memory-view.png`、`ui-audit/19b-memory-with-entries.png` vs 原型 `ucd-references/ucd-memory.png`。
- **修复方向**: 按 UCD 重排：索引健康条（已符合）→ 搜索框 + 类型胶囊 → 记忆卡片列表为主内容；保留集合/关系/提炼候选为次级区块。

### U-09 审批中心缺状态筛选与历史归档
- **UCD 依据**: §9.2.5 顶栏「状态: [待裁决 (1) ▼]」；第 3 条「历史审批归档 Tab：查看已批准、已驳回、已过期、已被取代的历史记录」。
- **现状**: 只有「刷新列表」按钮 + 空态「没有待裁决的请求。」；无状态筛选、无历史归档 Tab。
- **证据**: `ui-audit/20-approval-view.png`。
- **修复方向**: 补状态筛选与历史归档 Tab（或同步修订 UCD）。

### U-10 Composer 下出现内部术语提示，缺操作入口
- **UCD 依据**: §9.1.4 未定义「选择历史运行」类状态；用户文案不应暴露运行（run）内部概念。
- **现状**: 首页与项目对话的 Composer 下方常驻一行「请先选择历史运行，以继续查看或从已结束运行开始新一轮。」，且无可点击入口；发送键在运行结束后处于禁用样式。
- **证据**: `ui-audit/09-home-direct-chat.png`、`ui-audit/23b-batch-bar.png`。
- **修复方向**: 按运行状态给出可操作文案（如「上一轮已结束，发送新消息开始新一轮」并保证可发送）。

### U-11 首页欢迎卡提示与 Composer 实际能力矛盾
- **UCD 依据**: §9.1.1 欢迎卡「或直接在下方输入框开始 1:1 直聊」；§9.1.1 占位文字「输入消息，与助手直接对话…」。
- **现状**: 欢迎卡提示可直接直聊，但 Composer 禁用、占位为「新建对话后即可输入…」——需先手动新建对话；占位文案与 UCD 不一致。
- **证据**: `ui-audit/09-home-direct-chat.png`。
- **修复方向**: 二选一——允许首页直接输入（自动创建个人对话）；或修正欢迎卡文案与占位，明确「先新建对话」。

## P2 — 文案与细节

### U-12 无 Provider 空态文案与引导目标
- **UCD 依据**: §9.1.1「未配置 Provider 时卡片自动切换为『未配置 Provider』，主按钮变为『配置 Provider』」。
- **现状**: 文案「先配置一个 Agent，即可开始个人对话。」+ 按钮「配置 Agent」（链接 `/team?section=agents…`）；另空态下整个会话侧栏（240px）不渲染，与 §9.1.1 线框（三区常驻，含回收站入口）不符。
- **证据**: `ui-audit/01-home-no-provider.png`。
- **修复方向**: 文案与按钮对齐 UCD；或修订 UCD。侧栏缺失是否有意需产品确认。

### U-13 视图标题与泳道文案偏差
- **UCD/原型依据**: 原型「使命与任务看板 · <项目>」「共享记忆与知识库 · <项目>」；UCD §9.2.6「统一审计中心」；原型泳道「待办(Todo)/进行中 (In Progress)/阻塞 (Blocked)/完成 (Done)」。
- **现状**: 「任务看板 · <项目>」「共享记忆 · <项目>」「审计中心 · <项目>」；泳道仅中文（待办/进行中/阻塞/完成）；空泳道有「暂无进行中任务。」等文案（原型空泳道无文案）。
- **证据**: `ui-audit/18d-board-with-card.png`、`ui-audit/19-memory-view.png`、`ui-audit/21-audit-view.png`。
- **修复方向**: 统一文案；英文后缀与否先更新 UCD 再实现。

### U-14 审计事件时间未本地化
- **UCD 依据**: §9.2.6 时间轴/事件示例为本地短时（`[10:25:30]`）。
- **现状**: 事件行时间显示原始 ISO UTC 串（`2026-10-10T18:25:43.025Z`），与中文界面其余处的本地时间（`2026/10/11 02:25`）不一致。
- **证据**: `ui-audit/21-audit-view.png`。
- **修复方向**: 统一本地化时间格式（与聊天事实行一致）。

### U-15 批量整理交互条形态
- **UCD 依据**: §9.6.2「底部弹出浮动操作条：批量打标、批量星标、批量移入回收站，带幂等回执」。
- **现状**: 批量整理为侧栏内嵌面板（「批量整理 / 已选 N 条对话 / 应用更改 / ＋新建标签」），非底部浮动条件栏；功能可用、幂等回执已具备。
- **证据**: `ui-audit/23b-batch-bar.png`。
- **修复方向**: 形态对齐 UCD，或修订 UCD 记录现状。

### U-16 搜索浮层查询无结果展示（需复核）
- **UCD 依据**: §9.6.1「即时搜索对话标题、消息正文、参与 Agent」。
- **现状**: `Cmd+K` 打开浮层后输入「登录」（存在匹配对话「JWT 登录模块重构与双 Token 方案」），截图时点为无结果列表；未能确认是否需回车触发或存在渲染缺陷。
- **证据**: `ui-audit/12-search-overlay.png`、`ui-audit/12b-search-results.png`。
- **修复方向**: 复核即时结果渲染；若需回车，补充提示文案。

### U-17 项目切换瞬间的陈旧请求 404
- **UCD 依据**: AGENTS.md「切换必须使用规范目标身份与 abort/epoch 检查」。
- **现状**: 打开文件夹进入项目瞬间，旧个人对话 thread id 在新项目路径下产生 4 个 404（thread/messages/facts/draft）；界面无可见错误并自动恢复。
- **证据**: 运行日志（`RESOURCE_NOT_FOUND` 4 条，发生在 `15-project-empty` 前后）。
- **修复方向**: 切换时中止/清空旧目标请求（低风险优化）。

### U-18 /team 服务健康疑似裁切（需视口复核）
- **UCD 依据**: §9.3.6 四张卡片并排（应用/模型服务/记忆索引/执行），每卡一条脱敏说明与恢复按钮。
- **现状**: 全页截图中「服务健康」出现在左列窄栏内（应用/模型服务可见），下方内容截断，页面下部大面积空白；疑似 fullPage 截图与固定高度容器叠加的伪影，需在视口中确认是否为真实布局问题。
- **证据**: `ui-audit/26-team-overview.png`。
- **修复方向**: 视口复核；若为真实布局问题，按 §9.3.6 四卡并排呈现。

## 已核验为符合或非缺陷（防止误修）

- 侧栏筛选 Tab 选中态为浅金胶囊填充：**符合 UCD §7.1**（「胶囊式小标签」）；原型的下划线样式偏旧。
- 审计六域筛选（全部/执行/协作/任务/项目/治理/运行时）、列表/时间轴切换、导出脱敏包按钮、已追平徽标：符合 §9.2.6。
- 记忆索引健康条「索引已追平 · 2/2 有效」+「重建索引」：符合 §9.2.4。
- 输入历史面板（搜索、记录开关、清除全部）、`@`提及浮层、附件菜单、更多菜单/回收站、暗色主题、窄屏抽屉（含项目设置区块）：与 UCD 大体一致。
- 空对话态无 Composer、Needs Me 徽标仅在待处理时亮起：状态驱动，非缺陷。
- 治理视图点击时侧栏残留的「任务/审批/审计」小浮标为鼠标悬停 Tooltip 残留（截图现象），非布局缺陷。

## 覆盖限制

- §9.5 复核工作台本次未捕获（需完整执行→复核链，复用 `review-browser-smoke` 的环境可补）。
- 审批中心「待裁决卡片（TTL/Diff/批准驳回）」带数据状态、执行/交付回放详情未逐屏核验。
- `/team` 各 region 仅部分核验（Provider/技能/Agent 创建与保存流程正常）；§9.3.6~9.3.9 看板仅覆盖健康组与滚动位。
- 本清单只记录本次捕获范围内可证的差异；未覆盖不等于无问题。
