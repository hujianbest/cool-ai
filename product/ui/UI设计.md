## 2. 设计研究摘要

本设计基于 `@cursor/skills/ui-ux-pro-max` 技能库的系统检索，结合 Cool AI 本地优先、多 Agent 协作驾驶舱的真实约束进行参数调优与设计收敛。

### 2.1 技能检索参数与结论
根据驾驶舱定位，检索设定参数为：`--density 8`（紧凑驾驶舱）、`--variance 3`（克制极简）、`--motion 2`（安静微动效）。

| 维度 | 检索输出建议 | 在 Cool AI 中的设计采纳与落地 |
|---|---|---|
| **核心模式 (Pattern)** | Trust & Authority + Content-First Chat Shell | 建立以对话为中心的作业面；所有治理操作收归为按需视图；通过不可变时间线和可追溯来源建立确定性信任。 |
| **视觉风格 (Style)** | Minimalism & Swiss Style（极简主义） | 采用暖米画布与暖金强调，高留白、弱边框（1px hairline）、轻阴影；通过字重与明度建立信息层级，拒绝多余装饰。 |
| **交互原则 (UX)** | Focus Not Obscured + User Freedom + Active Feedback | 键盘焦点始终清晰可见且不被浮动栏遮挡；空状态提供明确下一步引导且允许自由跳过；状态切换在 80~150ms 内提供稳定反馈。 |
| **图标与无障碍 (Icons)** | Phosphor 线性矢量族 + 语义属性规范 | 统一采用 Phosphor 线性图标（描边 1.5px/2.0px）；严禁用 Emoji 作为系统结构图标；装饰图标 `aria-hidden="true"`，操作图标提供语义标签。 |
| **流式与响应 (Stack)** | Next.js Suspense + Streaming Composer | 对话流采用流式分块渲染，打字机滚动平滑无跳变；Composer 支持防抖与上下文即时加载。 |

### 2.2 核心反模式（严禁出现）
- ❌ **严禁主路径四栏常驻**：不再将使命看板、共享记忆、审批流、审计作为常驻右栏或并列面板强行塞在主屏。
- ❌ **严禁表单堆砌与未接线控件**：空状态或首页不铺陈复杂的未连接配置项；无项目时居中保持 1:1 纯净对话。
- ❌ **严禁手动输入本地文件路径**：打开与绑定工作区一律调用操作系统原生文件夹选择器，杜绝手动输入路径引发的格式与安全错误。
- ❌ **严禁 Emoji 充当结构图标**：导航栏、操作按钮、系统标签严禁用 📁、⚙️、🤖 等 Emoji 代替矢量图标。
- ❌ **严禁破坏历史与不可变性**：不以“最新状态”覆盖历史版本；任何由 Agent 产出的决定、执行与复核均保留冻结来源。

## 3. 目标用户与人物角色（Persona）

Cool AI 专为追求极致生产力、拥有全栈实现能力的独立创造者打造。

### 主 Persona：Alex —— 独立产品创造者（Solo Indie Creator）

```text
┌────────────────────────────────────────────────────────────────────────┐
│  Alex | 31 岁 | 独立全栈开发者 / 独立数字产品创造者                      │
│  工作方式：单兵作战，推动 1~2 个真实产品从创意、架构、编码到上线运营     │
│  工作环境：macOS / Windows 桌面工作站，熟悉 CLI 与 Git，配置有 API Key  │
│  性格特征：追求专注与心流，注重代码与资产所有权，对黑盒不可控工具极度敏感 │
└────────────────────────────────────────────────────────────────────────┘
```

- **典型日常**：
  - 在本地打开项目代码或设计资料文件夹。
  - 需要一个“规划伙伴”帮忙拆解架构任务，一个“编码搭档”快速执行受控改动，一个“挑剔同事”独立复核代码。
- **心理诉求**：
  - **掌控感**：我必须是唯一的决断者（Owner），Agent 可以提出建议或执行任务，但关键动作必须经我同意，且执行结果必须有据可查。
  - **免维护路由**：受够了在 Web 聊天窗口中手动复制粘贴：“A 模型给出的方案，复制给 B 模型修改，再复制给 C 模型检查”。
  - **安静与专注**：工作台必须干净，不要花哨的 3D 动画、不要杂乱的仪表盘堆叠，让我能够连续工作数小时而不产生视觉疲劳。

## 4. 要完成的工作（JTBD）与痛点对照

### 4.1 核心 JTBD 声明
> **当**我需要独自推进一个复杂的产品功能或架构迭代时，  
> **我想要**把规划、实施、复核等多名专业 Agent 组织进我本地打开的项目中，并在一个公开透明的对话流中发起协作与交棒，  
> **以便于**它们能够自主讨论、受控执行并独立验证，而我无需充当人工路由器，同时对整个过程保持绝对掌控与可追溯性。

### 4.2 核心痛点与 UI 解决方案矩阵

| 序号 | 用户的核心痛点 | 传统工具的缺陷 | Cool AI 的 UI/UCD 解决方案 |
|---|---|---|---|
| **P-1** | **人工路由器疲劳** | 多个 AI 窗口各自为政，用户频繁复制粘贴上下文。 | **共享公开会话**：Owner 在居中聊天流发起任务，自带 Agent 在同一时间线内自主接力、互相引用与交棒。 |
| **P-2** | **操作黑盒与越界恐惧** | 自动 Agent 随意修改本地文件，出了问题难以回滚。 | **统一审批与对话流内联证据**：高危动作触发 Header 暖金「Needs Me」徽标与内联卡片，清晰展示影响范围。 |
| **P-3** | **多栏堆叠造成认知过载** | 屏幕被项目树、看板、记忆、聊天、终端切成 4~5 列，极其压抑。 | **52px 图标轨 + 240px 侧栏 + 840px 居中流**：治理能力收归图标轨，按需唤起，一键「返回对话」。 |
| **P-4** | **无项目时的挫败感** | 刚进入必须先建库、建项目、配工作区，无法立即使用。 | **开箱即用 1:1 直聊 + 原生选夹**：未选项目时即为极简对话；选夹直接调起系统选择器，自带 3 名 Agent 秒级就绪。 |
| **P-5** | **上下文丢失与虚假记忆** | 每次刷新或重启，AI 忘了之前的决定，或编造历史。 | **持久对话与冻结来源导航**：消息以不可变块存储，关键结论带精确引用（Source Tuple），随时可溯源。 |

## 5. 关键用户场景（Key User Scenarios）

### 场景 1：首次打开（无 Provider 引导）
- **情境**：用户首次安装并启动 Cool AI，本地未配置任何模型 API。
- **界面行为**：
  - 图标轨与侧栏以骨架/就绪状态呈现；
  - 聊天主区居中显示欢迎卡片，文案克制友善：“欢迎使用 Cool AI。配置模型 Provider 后即可开始。”；
  - 呈现醒目的暖金主按钮「配置 Provider」及次级「查看引导」；
  - 点击直达 `/team` 或全局设置中的 Provider 配置弹窗，配置成功后平滑返回，无刷新白屏。

### 场景 2：打开文件夹进入/恢复项目（阶段 1 核心路径）
- **情境**：用户准备开始处理本地的 `cool-mobile` 项目。
- **界面行为**：
  - 用户点击 Header 右上角的「打开文件夹」按钮（或快捷键 `Cmd/Ctrl + O`）；
  - 浏览器调用操作系统原生文件夹选择器（File System Access API）；
  - 用户选中目录后，系统校验目录权限并绑定为当前 Project；
  - 侧栏立即恢复或创建该项目的持久对话；主区就绪，自动载入该项目的规划、实施、复核 3 名自带 Agent。
  - **严禁**提供任何手动输入路径的文本框。

### 场景 3：未选项目时的 1:1 直聊（阶段 1 核心路径）
- **情境**：用户刚打开应用，只想快速问一个算法问题或头脑风暴，不想绑定本地文件夹。
- **界面行为**：
  - Header 显示「未选择项目」，语境为「个人对话」；
  - 居中聊天流保持清爽，Composer 占位符提示“输入消息，与助手直接对话…”；
  - 具备完整的流式输出、复制、重试与 Markdown 渲染能力，体验轻快顺畅。

### 场景 4：对自带 Agent 公开发言与 @Agent 接力
- **情境**：在已绑定项目中，用户希望规划 Agent 梳理登录模块改造方案，并由实施 Agent 执行。
- **界面行为**：
  - 用户在底部 Composer 输入 `@`，弹出 Agent 快速选择浮层（规划、实施、复核）；
  - 选中「@规划」，输入“请分析当前登录模块的重构步骤”并发送；
  - 聊天流出现规划 Agent 的思考过程与流式输出；
  - 输出完毕后，规划 Agent 生成结构化任务卡片，并自动 `@实施 请根据方案进行文件改动`；
  - 协作时间线以公开气泡形式自然流转，用户作为 Owner 全程可见并随时可插话打断。

### 场景 5：打开治理视图并无缝返回对话
- **情境**：在协作过程中，用户想查看当前项目的任务依赖全景或记忆沉淀。
- **界面行为**：
  - 用户点击左侧 52px 图标轨的「任务」图标；
  - 居中聊天流平滑切换为全宽任务视图，展示 Mission 与 Work Item 进展；
  - 视图左上角显式保留 `← 返回对话` 暖金按钮；
  - 用户完成浏览或微调后，点击按钮（或按 `ESC` 键，或点击图标轨「对话」图标），主区立即恢复原会话流，保留滚动锚点与正在输入的草稿。

### 场景 6：统一审批与 Needs Me 响应
- **情境**：实施 Agent 在绑定工作区内准备写入修改文件 `auth.ts`，触发安全策略。
- **界面行为**：
  - 对话流中生成结构化审批卡片（清晰列出：待修改文件、Diff 预览、发起 Agent、操作风险评级）；
  - 顶部 Header 右侧与图标轨「审批」图标即刻亮起暖金「Needs Me」徽标；
  - 用户在卡片上直接点击「批准（Approve）」或「拒绝（Reject）」，亦可在审批中心统一批复；
  - 操作后卡片变为已审批状态，Agent 收到确认信号继续执行，整个过程可审计。

### 场景 7：异常与网络超时防御
- **情境**：调用模型 API 发生网络抖动或鉴权失效。
- **界面行为**：
  - 消息气泡下方出现温和的错误提示条（采用 `--color-surface-pearl` 底色与暗红警示字，脱敏报错信息，绝不暴露内部堆栈或系统绝对路径）；
  - 提供「重试」与「检查 Provider」快捷按钮；
  - 系统维持失败关闭原则，不生成虚假成功事实。

### 6.2 主路径与支路步骤规范

1. **第 1 步：环境就绪**
   - 检查本地数据库与 Provider。未就绪则停留在欢迎引导，不展示破损界面。
2. **第 2 步：语境锚定**
   - 用户打开目标文件夹，Header 更新为 `[项目名] · [对话标题]`，侧栏高亮当前对话。
3. **第 3 步：意图输入**
   - 用户在底部 Composer 输入文本或 `@Agent`。输入框自适应扩展高度，最大支持 6 行滚动。
4. **第 4 步：公开流式协作**
   - 目标 Agent 响应，输出流式 Markdown。其他 Agent 根据讨论逻辑自主接力，过程透明。
5. **第 5 步：治理干预（按需）**
   - 遇到审批时快速处理；若需全局洞察，点按图标轨打开任务/记忆/审批/审计/设置，随时按 `ESC` 返回。
6. **第 6 步：闭环沉淀**
   - 任务由非执行者 Agent 独立复核，裁决通过后沉淀为持久记忆与交付物，结束会话节点。

### 7.1 桌面三区详细定义

#### 区域 A：52px 图标轨（Activity Bar）
- **定位**：全局能力与治理视角的唯一一级切换中枢，常驻屏幕最左侧。
- **背景**：`--color-rail`（亮 `#EAE4DA` / 暗 `#16130F`）。
- **内容组织**：
  - **顶部主项组**：
    1. `对话`（MessageSquare 图标）：主路径入口，默认激活。
    2. `任务`（CheckSquare 图标）：按需打开当前项目的使命与任务看板视图。
    3. `记忆`（Brain 图标）：按需打开当前项目的结构化记忆与知识库视图。
    4. `审批`（ShieldCheck 图标）：打开统一审批中心；有待处理项时右上角显示暖金红点。
    5. `审计`（ListMagnifyingGlass 图标）：打开系统审计日志与事件时间轴。
  - **底部分组（经分割线隔离）**：
    6. `团队`（Users 图标）：直达 Agent 编排与 Provider 配置（`/team`）。
    7. `设置`（Gear 图标）：打开全局偏好设置。
    8. `主题`（Sun / Moon 图标）：一键切换亮/暗视觉主题。

#### 区域 B：240px 会话侧栏（Conversation Sidebar）
- **定位**：对话列表与切换面板，管理当前项目的公开协作容器。
- **背景**：`--color-canvas-parchment`（亮 `#FAF6F1` / 暗 `#26221D`）。
- **内容组织**：
  - **头部**：左侧大字标题「对话」（16px 600），右侧「+ 新对话」胶囊图标按钮（44px 触区）。
  - **筛选 Tab**：胶囊式小标签（全部、收藏、标签），高 32px，支持即时过滤。
  - **对话列表**：
    - 单项高 44px，展示：对话标题（超长省略）、最后活跃时间（12px muted）、参与 Agent 迷你头像组、正在运行中的暖金呼吸点。
    - 选中态：左侧 3px 暖金指示条 + 背景高亮（`--color-surface-pearl`）。
  - **底部固定项**：高 44px 的「回收站」入口，支持已软删除会话的查看与还原。

#### 区域 C：聊天主区与按需治理区（Main Stage）
- **定位**：用户与 Agent 的工作台。
- **背景**：`--color-canvas`（亮 `#F4EFE7` / 暗 `#1E1B17`）。
- **内容组织**：
  - **顶部 Header (48px)**：
    - 左侧：产品品牌标识「Cool AI」。
    - 中间：当前项目名与当前对话标题（如 `cool-mobile · 登录模块重构`）。
    - 右侧操作区：
      - 「打开文件夹」按钮（带系统文件夹图标，44px 触区）。
      - 「Needs Me」状态徽标（当有待办审批时高亮呈现，点击呼出审批详情）。
  - **居中聊天流 (Centered Chat Flow)**：
    - 最大宽度限制为 **840px**，水平居中。
    - 垂直方向弹性滚动，底部预留 120px 的 Scroll-Padding 避免内容被 Composer 遮挡。
  - **浮起 Composer (Floating Composer)**：
    - 宽度与聊天流对齐（最大 840px），浮动在底部 24px 处。
    - 样式：背景 `--color-surface-pearl`，圆角 12px，1px 弱边框 `--color-hairline`，极轻环境阴影。
    - 结构：左侧「添加附件/上下文」图标按钮（44px）、中间自适应多行输入框、右侧「发送/停止」主按钮（44px）。
  - **按需治理视图 (On-Demand Governance View)**：
    - 当从图标轨点击任务/记忆/审批/审计时，替代聊天流填满主区。
    - 顶部固定工具栏始终提供 `← 返回对话` 按钮，并在右上方保留上下文筛选。

### 7.2 响应式断点与退化策略

| 屏幕宽度 | 布局形态 | 侧栏行为 | 图标轨行为 | 聊天流宽度 |
|---|---|---|---|---|
| **≥ 1280px (宽屏)** | 三区完整展开 | 240px 常驻展开 | 52px 常驻 | 840px 居中 |
| **1024px ~ 1279px (标屏)** | 三区完整展开 | 240px 常驻展开 | 52px 常驻 | 自适应居中 (最大 840px) |
| **768px ~ 1023px (平板/窄屏)** | 抽屉模式 | 收起为抽屉，通过 Header 汉堡按钮呼出 | 52px 常驻 | 100% 宽度 (水平 Padding 24px) |
| **< 768px (极窄/移动)** | 极简模式 | 全屏抽屉滑出 | 底部 Tab 栏或 52px 紧凑轨 | 100% 宽度 (水平 Padding 16px) |

## 8. 交互设计原则与模式规范

### 8.1 选中态规范（Active States）
- **图标轨**：选中项图标颜色切换为暖金（亮 `#9A5F1A` / 暗 `#E4B066`），左侧出现 3px 宽、圆角 2px 的暖金垂直指示条。
- **对话列表**：选中项背景填充 `--color-surface-pearl`，文字字重提升至 600，右侧显示当前对话的活动状态徽标。
- **筛选胶囊 Tab**：选中项底色应用 `--interactive-accent-soft`（亮 `#FDF3E0` / 暗 `#3A2E1E`），文字为暖金主色。

### 8.2 Tooltip 触发与展示机制
- **延迟与过渡**：悬停（Hover）200ms 后浮现，鼠标移开立即消失；过渡时长 150ms。
- **位置与避让**：图标轨 Tooltip 固定向右弹出，垂直居中对齐；避开视口边缘。
- **无障碍实现**：原生结合 `title` 与 `role="tooltip"`，并通过 `aria-describedby` 关联。

### 8.3 模态对话框与弹出层规范（Modal & Dialog）
- **层级与遮罩**：遮罩层（Scrim）采用 `rgba(20, 16, 10, 0.4)`，背景应用 4px 轻微模糊。
- **容器规格**：圆角 16px，背景 `--color-surface-pearl`，内边距 24px，最大宽度通常为 520px（表单）或 720px（复杂工作区）。
- **焦点捕获与关闭**：
  - 弹出后焦点自动落入首个输入框或主确认按钮；
  - 严格限制 `Tab` 键在弹窗内循环（Focus Trap）；
  - 按 `ESC` 键或点击遮罩区域立即关闭，焦点平滑归还原触发点。

### 8.4 返回对话机制（Back-to-Chat Pattern）
- **单一退出通道**：所有从图标轨打开的二级治理视图（任务、记忆、审批、审计、设置），在视图 Header 最左侧提供明确的 `← 返回对话` 按钮。
- **快捷键直达**：在任何治理视图中，按下 `ESC` 或 `Cmd/Ctrl + 1` 均可瞬间返回对话主路径。
- **状态保持**：返回对话时，自动恢复前序会话的滚动进度、Draft 输入草稿和展开状态。

### 8.5 原生选夹交互流（Native Folder Picker）
- **触发入口**：Header「打开文件夹」按钮及空状态主操作。
- **API 管道**：调用 `window.showDirectoryPicker()` 原生接口。
- **异常捕获**：
  - 若用户在系统对话框中点击“取消”，界面保持原状，不弹出多余报错。
  - 若用户选择受限系统目录（如根目录或系统临时文件），弹出友好提示条解释安全规则并建议重新选择。

### 8.6 Composer 键盘与富交互规范
- **@ 唤起与过滤**：在输入框键入 `@` 时，光标上方弹出 Agent 列表菜单，支持键盘上下方向键导航、`Enter` 或 `Tab` 键自动补全。
- **发送与换行**：`Enter` 触发发送，`Shift + Enter` 插入换行符。
- **高度自适应**：初始单行（44px 触区），随内容增加自动弹性撑高，最高 180px，超出后出现内置滚动条。
- **附件操作**：支持直接将本地图片或文件拖拽入 Composer，或按 `Cmd/Ctrl + V` 粘贴剪贴板图片，生成内联预览小卡片并支持一键删除。

### 8.7 键盘导航与焦点管理（Keyboard & Focus）
- **全局快捷键表**：
  - `Cmd/Ctrl + K`：全局对话与命令搜索。
  - `Cmd/Ctrl + N`：新建对话。
  - `Cmd/Ctrl + O`：调出系统文件夹选择器打开项目。
  - `Cmd/Ctrl + B`：展开/折叠会话侧栏。
  - `Cmd/Ctrl + 1`：快速切换至「对话」主路径。
  - `Cmd/Ctrl + 2~5`：按序唤起任务、记忆、审批、审计视图。
  - `ESC`：关闭当前弹窗 / 从治理视图返回对话。
- **焦点环（Focus Ring）**：
  - 所有可聚焦控件在 `:focus-visible` 下显示 2px 暖金焦点环（`--color-primary`），`outline-offset: 2px`。
  - 严禁出现 `outline: none` 而不提供视觉替代。

### 9.1 主驾驶舱主路径（The Main Cockpit Surface）

#### 9.1.1 首页与 1:1 直聊页面（`/`，Home & Direct Chat View）

## 11. 无障碍（Accessibility）与紧凑设计契约

### 11.1 对比度保证（WCAG 2.2 AA）
- **正文文字**：主文字 `--color-ink` 对画布背景对比度严格 **≥ 7:1**（远超 4.5:1 基准）。
- **次级文字**：`--color-ink-muted-80` 对背景对比度严格 **≥ 4.5:1**。
- **弱化文字与边界**：`--color-hairline` 与图形边界对比度严格 **≥ 3:1**。
- **主题独立验证**：亮色主题与暗色主题各自独立测量验证，禁止用同一套相对值换算。

### 11.2 触控与点击目标（Touch Target ≥ 44×44px）
- 即使视觉呈现为 20px 的小图标或 32px 的胶囊标签，其 CSS 物理外延或虚拟伪元素（`::after`）点击响应热区必须 **≥ 44×44px**。
- 保证在触控屏或高分辨率触控板上均可轻松点击，避免误触。

### 11.3 语义树与 ARIA 规范
- **图标语义解耦**：
  - 纯装饰性图标显式添加 `aria-hidden="true"`；
  - 独立操作图标按钮必须配置 `aria-label` 明确描述动作（如 `aria-label="新建对话"`）；
  - 折叠/展开控件关联 `aria-expanded="true/false"`；
  - 切换类按钮关联 `aria-pressed="true/false"`。
- **实时区域（Live Regions）**：
  - 对话流的流式输出外层容器配置 `aria-live="polite"` 与 `aria-atomic="false"`，确保屏幕阅读器能有序朗读而不打断用户操作。

### 11.4 减弱动效适配（`prefers-reduced-motion`）
- 当检测到系统开启减弱动效时：
  - 彻底关闭页面滑动、弹窗位移及复杂过渡；
  - 将所有动效降级为平滑透明度淡入淡出（Opacity Fade），时长压缩至 ≤100ms；
  - 停止所有呼吸灯光晕动画，转为静态色彩指示。
