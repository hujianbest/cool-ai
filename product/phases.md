## 第一性原理

Cool AI 的定义是：单一 owner 把平等角色 Agent 组成项目组，围绕打开的本机文件夹公开协作并交付可追溯成果。

因此第一阶段只证明三件事：

1. **有工作对象**：用操作系统资源管理器选中文件夹，进入或恢复 Project（不要让 owner 手输路径）。
2. **有作业班组**：不要求从零创建角色；系统提供规划 / 实施 / 复核三名自带 Agent（已有模板落地为真实 Agent）。
3. **有公开作业面**：中间是会话与 composer（对齐 [pi-web-ui](https://github.com/badlogic/pi-mono) 与 [DeepSeek Harness Web UI](https://github.com/deepseek-ai/deepseek-harness) 的 session + chat，不复制其品牌或源码）。

使命看板、共享记忆、SOP、能力画像、HelpTip 气泡不是「能开始作业」的前提。它们属于更后阶段的治理表面。

交互参考（只取信息架构，不拷贝资产）：

- pi：左会话 / 中聊天 / 底栏 composer；工具结果在对话流里，而不是四个常驻治理面板。
- DeepSeek Harness：`Choose workspace` 走宿主 `directory-picker-native`（系统文件夹对话框），选中工作区后 composer 才可用；不在页面里填路径。

## 阶段

切片: 050 / S-60。

Owner 能：用系统文件夹选择器打开项目；在已有模型服务时立即拥有三名自带 Agent 并自动入组；在聊天优先驾驶舱里与他们公开对话。使命、记忆、看板、HelpTip 不在该表面展示。

仍要配置一次 OpenAI-compatible 模型服务（凭据不能伪造）。没有 Provider 时明确引导去 `/team`，不假装能发模型调用。

在对话流中暴露工作区读取/变更、命令与审批（既有 `CAP-EXE-01` / `CAP-GOV-*`），不把执行藏在独立「运行详情」百科里作为主路径。
