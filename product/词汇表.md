# 领域词汇表（统一语言）

- 日期: 2026-08-16
- 状态: 生效。本文件是 Cool AI **统一语言（Ubiquitous Language）** 的单一事实源。
- 依据: DDD 战略设计；2026-08-16 对照主流 Agent 系统刷新（D-53）；限界上下文对齐 [`architecture.md`](./architecture.md) 第 2、15 节；用户可感知用语对齐 [`ui/UI设计.md`](./ui/UI设计.md)。
- 关联: [`README.md`](./README.md) · [`product.md`](./product.md) · [`architecture.md`](./architecture.md)

规格说明书回答「做什么」；架构说明书回答「边界与不变量」；本文件回答「同一个词在对话、规格、代码与界面里必须指同一件事」。新切片的 spec / DTO / UI 文案不得另造同义术语。

代码标识若仍写历史英文（如 `Thread`），**产品语言以本表领域词为准**；机械重命名另开切片，不在本文把旧标识说成推荐用词。

## 0. 使用规则

1. **中英对照固定**：下表「领域词」是中文产品用语，「推荐英文」是统一语言的英文；「代码标识」记录当前仓库符号，便于对照，不是推荐文案。
2. **一词一义**：每个领域词只属于一个限界上下文的命令事实；跨上下文只能引用身份与冻结快照，不能改写对方的词。
3. **禁止用技术层偷换**：页面、路由、投影、SQLite 表不是领域概念。例如「审计面板」是 UI；审计事件的命令事实仍在各 source owner。
4. **新增或改词**：先改本文件并在 [`decisions.md`](./decisions.md) 留痕，再进入 implement。不得在代码里先发明、文档后补。
5. **易混对以第 6 节为准**：出现争议时，本文件优先于聊天记忆、UI 草稿和旧 feature 文案。
6. **对照外部系统只取原则**：可借鉴 Pi / DeepSeek Harness 的 Session、ChatGPT 的「对话」；不把 Codex `Thread`、OpenClaw 的 IM thread、AutoGen GroupChat、CrewAI Crew 拷进产品语言。

## 1. 战略划分（核心 / 支撑 / 通用）

Cool AI 的**核心域**是：单一 owner 组织平等角色 Agent，在打开的本机文件夹上公开协作，并经独立复核交付可追溯成果。其余上下文支撑该闭环，或提供可替换的技术能力。

| 子域类型 | 限界上下文 | 一句话 |
|---|---|---|
| **核心** | Public Collaboration | 公开对话、消息、交棒、就地决策 |
| **核心** | Mission & Work | 使命、工作项、依赖、派发租约（任务真相） |
| **核心** | Review & Delivery | 非执行者复核、交付包、完成门槛 |
| 支撑 | Identity & Capability | Provider、Agent、Skill、能力声明 |
| 支撑 | Project & Workspace | Project 身份、成员、绑定根、浏览 |
| 支撑 | Safe Execution | 隔离执行、验证、暂存变更、合入 |
| 支撑 | Governance | Approval 请求与裁决（不是业务成功） |
| 支撑 | Knowledge & Provenance | 带来源的记忆与 supersedes 链 |
| 通用 | Runtime | 外部调用传输会话、effective grant 投影、通知 |
| 通用 | Operations Projection | 可重建的审计/搜索/时间轴读模型 |

限界上下文之间的关系（上下文地图）见架构说明书第 15 节。本文件只固定**词**，不重复依赖方向矩阵。

## 2. 角色与主体

| 领域词 | 推荐英文 | 代码标识 | 含义 | 不是 |
|---|---|---|---|---|
| Owner | Owner | `owner` | 唯一人类决策者；对方向、授权和人工判断有最终决定权 | 账号系统、多租户用户、管理 Agent |
| Agent | Agent | `Agent` | 稳定角色身份：职责、模型绑定、技能与工具权限可配置；项目组内平等 | Provider、模型名称、一次 API 调用 |
| 自带 Agent | built-in Agent | templates → 真实 `Agent` | 规划 / 实施 / 复核三名模板落地后的真实 Agent | 不可编辑的系统幽灵角色 |
| 复核者 | Reviewer | reviewer Agent | 合格**非执行者** Agent，对冻结材料做真实模型复核 | 执行同一工作项的 Agent、平台自动打分 |
| 项目成员 | Project Member | `ProjectMember` | Agent 在某 Project 中的成员关系 | Agent 全局身份本身 |
| 平台 | Platform | platform | 校验成员、限额、安全与持久化；**不**做业务决策 | 隐藏的总管 Agent |

## 3. 跨上下文不变量用语

这些词不属于单一业务上下文，但所有上下文必须同义使用。

| 领域词 | 推荐英文 | 代码标识 | 含义 | 规则 |
|---|---|---|---|---|
| Ownership Tuple | Project / Session / Run | `projectId` / `threadId` / `runId` | 协作与下游事实的联合身份 | 跨 tuple 访问失败关闭；口语与规格说 Session，列名暂仍 thread |
| 冻结来源 | Frozen Source Tuple | Frozen Source Tuple | 动作开始时冻结的 Project、对话、Run、Message 及适用实体/版本 | 恢复、复核、投影、交付不得替换成 latest |
| 操作 | Operation | `operationId` + request hash | 写命令的幂等身份 | 同 ID+hash 重放同一结果；同 ID 不同 hash 冲突 |
| 期望版本 | Expected version | `expectedVersion` | 命令层并发前置 | create 用 `not-exists/0` 或 stream head；子事实不伪造独立版本 |
| 租约 | Lease | `lease` | 跨时间占有资源的令牌/期限/心跳 | 单事务动作不得制造虚假长租约 |
| 三阶段协议 | Acquire / Checkpoint / Finalize | 同左 | 外部或长时工作的短事务取得 → 有界进度 → 短事务终态 | 崩溃不得补造业务成功 |
| 公开事件 | Public event | outbox envelope | 命令事务内追加的脱敏跨域通知 | 仅有明确消费者才公开；不是事件溯源账本 |
| 投影 | Projection | projection | 可丢弃重建的读模型 | 不是命令事实源，不能回写 |
| 失败关闭 | Fail-closed | fail-closed | 未知、越界、脱敏失败时拒绝并保持可解释错误 | 不得伪造成功或静默丢弃 |

## 4. 按限界上下文

### 4.1 Identity & Capability

| 领域词 | 推荐英文 | 代码标识 | 含义 | 不是 |
|---|---|---|---|---|
| Provider | Provider | `Provider` | owner 配置的 OpenAI-compatible 模型服务身份与加密凭据引用 | 一次聊天调用、Runtime 传输会话 |
| 技能 | Skill | `Skill` | 可版本化、可分配的文本指令包 | 可执行插件、MCP 工具 |
| Agent 模板 | Agent Template | `AgentTemplate` | 规划/实施/复核等可编辑角色模板 | 已入组的 ProjectMember |
| 能力声明 | Capability | tool permissions | Agent **被配置为可以请求**的工具、预算与能力 | 某次执行已获授权 |
| 能力画像 | Capability insight | capability insight | 基于实际配置的只读解释与路由建议 | 自动改写角色或权限 |

### 4.2 Project & Workspace

| 领域词 | 推荐英文 | 代码标识 | 含义 | 不是 |
|---|---|---|---|---|
| Project | Project | `Project` | 协作与交付的隔离边界与身份 | 文件夹、Git 仓库、工作区内容 |
| 绑定根 | Workspace root | binding | 打开文件夹得到的唯一已验证目录根 | Project 本身 |
| 工作区 | Workspace | workspace | 绑定根上的受控文件能力（浏览/执行 Adapter） | 数据库、记忆库 |
| 打开文件夹 | Open folder | open-folder create-or-resume | 用系统选择器进入或恢复 Project | 手输路径、先填项目名再绑定 |
| 个人对话 | Personal session | home 1:1 | 未选 Project 时与一名 Agent 的对话 | 多 Agent 公开对话、使命看板 |
| 验证策略 | Validation policy | `ValidationPolicy` | 项目允许的校验命令与工作目录策略 | 一次执行的验证结果 |

### 4.3 Mission & Work

| 领域词 | 推荐英文 | 代码标识 | 含义 | 不是 |
|---|---|---|---|---|
| 使命 | Mission | `Mission` | 项目目标、完成门槛与工作项的唯一业务边界 | 对话、一次 Run、看板 UI |
| 工作项 | Work Item | `WorkItem` | 使命下唯一有效的任务事实：负责人、依赖、状态、版本 | 聊天里的待办句子、Execution |
| 依赖 | Dependency | dependency DAG | 工作项之间的前置关系 | 图布局、SOP 文件 |
| 派发租约 | Dispatch lease | dispatch lease | 进行中工作项的跨时占有（token / expiry / heartbeat） | Governance Approval |
| 流程状态 | SOP state | SOP state | 对照仓库流程文件与工作项的**只读**投影 | 第二套任务状态机 |

UI 可将工作项呈现为「任务」，但规格、DTO 与写路径必须用 Work Item；「任务」不得成为第二个事实源。

### 4.4 Public Collaboration

行业对照见第 8 节。持久协作容器的产品词是 **对话（Session）**，不再使用「线程」。

层级（与 Pi / DeepSeek Harness / AI coding dictionary 一致）：

**对话 Session → 回合 Turn → 模型请求 / 尝试 Attempt**

| 领域词 | 推荐英文 | 代码标识 | 含义 | 不是 |
|---|---|---|---|---|
| 对话 | Session | `Thread`（待重命名） | 项目内稳定、可列出/收藏/标签/回收的公开协作容器；标题不承担身份 | Mission、Run、OS 线程、论坛/IM 子楼、Codex API 的 Thread 文案 |
| 成员策略 | Member policy | `MemberPolicy` | 该对话内可发言/可调度成员的不可变版本 | 项目 roster 的自动镜像 |
| 协作运行 | Collaboration Run | `CollaborationRun` | 一次公开协作生命周期，**归属一个对话**；同一项目最多一个非终态 Run | Execution、对话本身、Runtime 传输会话 |
| 回合 | Turn | Turn | 一次被接纳的 owner 输入，直到 Agent 交还控制；其间可有多次模型请求与工具动作 | 工作项状态迁移、一次 HTTP 调用、整个对话 |
| 尝试 | Attempt | Attempt | 回合内一次模型调用（含修复重试） | Turn 本身 |
| 公开消息 | Message | Message / Thread Fact | 进入可见、可追溯项目事实的正式内容 | Provider 原始响应、隐藏推理 |
| 结构化块 | Structured Block | Structured Block | 提案、清单、交棒、文件引用等 allowlist 块 | 自由 Markdown 的临时样式；不必改称 Codex Item |
| 就地决策 | Inline Decision | Inline Decision | 在原消息块上完成的允许决定及 Action Receipt | Governance Approval |
| 交棒 | Handoff | handoff | Agent 显式把下一棒交给组员 | 平台暗中调度 |
| 回复引用 | Reply snapshot | reply snapshot | 写时冻结的来源消息快照 | 运行时再去取 latest |
| 草稿 | Draft | `ThreadDraft` | 按对话保存的未发送输入 | 公开消息 |
| 队列 / Steer | Queue / Steer | message queue | 未执行消息的等待、重排、撤回与受控调整（Pi/Harness 同名 steer） | 修改已完成的公开事实 |

## 5. 主要聚合（战术目录）

「聚合」在本产品中对应**写命令的父一致性边界**（operation/version/lease 作用在这一层）。子记录是不可变 child fact，不拥有虚构的独立 expected version。

| 限界上下文 | 聚合根（领域词） | 典型子事实 |
|---|---|---|
| Identity & Capability | Provider / Agent / Skill | 凭据信封、能力声明、验证结果 |
| Project & Workspace | Project | Member、Workspace binding、ValidationPolicy |
| Mission & Work | Mission | WorkItem、dispatch lease、status 变更 |
| Public Collaboration | 对话 Session；CollaborationRun | Message、公开事实、Block、Draft、Queue、MemberPolicy |
| Safe Execution | Execution | Attempt、Action、Staged Change、Merge Journal |
| Governance | Approval Request | 裁决、失效、授权证据 |
| Review & Delivery | ReviewAttempt；Delivery | Result 版本、证据清单 |
| Knowledge & Provenance | Memory（chain） | source 边、supersedes、active 标记 |

值对象（无独立生命周期，随命令冻结或拷贝）：Frozen Source Tuple、operation/hash、lease token、credential envelope、reply snapshot、source identity。

## 6. 禁用同义与易混对

| 不要说 / 不要当成同一个东西 | 要说 | 原因 |
|---|---|---|
| **线程**（产品文案） | **对话（Session）** | 「线程」在中文里首先是 OS thread / 论坛楼层 / Slack 子楼；界面已写「对话」。D-53 |
| Codex Thread / Clowder thread 直接当作用户词 | 对话 Session | 只借鉴信息架构，不跟外部 API 词 |
| 文件夹就是项目 | 文件夹是绑定根；打开文件夹进入或恢复 Project | D-47；工作区 ≠ Project |
| 仓库 / repo | Project 或绑定工作区（看你指身份还是文件树） | 产品领域不是 Git 托管 |
| 聊天 / 群聊当作任务真相 | 对话是公开协作容器；Mission/WorkItem 是任务真相 | 禁止第二套任务状态机 |
| 对话 = 协作运行 | 对话可跨越多次 Run；Run 是一次协作生命周期 | 切换对话不迁移 Run（D-32 语义仍有效） |
| 对话 = Runtime 会话 | 对话是产品容器；传输会话是 Adapter 调用 | OpenClaw 也区分 session 与外部 conversation |
| Run = Execution | CollaborationRun 是公开协作；Execution 是隔离工具动作 | 二者可关联，身份不同 |
| 回合 = 一次 API 调用 | 回合可持续多次模型请求与工具动作，直到交还 owner | Pi / Harness / dictionary 的 Turn |
| 审批 = 复核 | Approval 授权高风险动作；Review 判定交付是否通过 | 执行者不能既审批又复核完成 |
| 就地决策 = 审批 | Inline Decision 是协作块上的允许决定；高风险仍走 Approval | 卡片点击不是批准 |
| 记忆 = 聊天记录 | Memory 必须有来源与类型；原始消息不会自动升级 | 知识治理原则 |
| 最新消息 / latest | 冻结来源与版本 | 禁止用最新替换已选来源 |
| grant / 权限（统称） | 配置权限、项目范围、Approval、effective grant 四分 | 架构第 2 节权限事实 |
| 通知过了就是批准 | 通知只提醒 | D-25；通知无业务写权 |
| 看板 / SOP 文件 | 只读投影；写仍落 WorkItem | 投影不是命令源 |
| Task（历史表/旧 DTO） | 新写路径用 Work Item；旧 `TaskRun` 不作为产品词扩散 | 避免双轨 |
| Crew / GroupChat / Ralph loop | 不用 | 不是本产品的协作模型 |

## 7. UI 表面对照
