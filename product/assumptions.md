# 假设台账

agent 替用户做的默认选择。遇到欠定点的标准动作: 提出带默认值的选项 →
记录一条假设 → 继续推进；禁止静默填补。
状态: 生效 | 已确认（迁入 decisions.md）| 已推翻（评估波及,回对应阶段返工）。
格式: `- A-<n> <日期> [状态] <假设内容> — 默认理由: <一句话>`

- A-1 2026-07-29 [生效] 技术栈采用 Next.js + React + TypeScript + SQLite 的单仓 Web 应用 — 默认理由: 前后端一栈、本地启动简单，适合快速形成可演示闭环
- A-2 2026-07-29 [生效] 产品本地优先、单机运行且首版不做登录；敏感配置只保存在服务端本地 — 默认理由: 目标用户是单 owner，先避免无价值的账号与部署复杂度
- A-3 2026-07-29 [生效] 提供“规划、实施、复核”三个可编辑角色模板，但模板之间没有固定上下级，owner 可删除、改名或新增角色 — 默认理由: 降低首次组队门槛，同时保持角色可配置和平等协作
- A-4 2026-07-29 [生效] 每次 Agent 输出必须明确选择“交棒给某位组员”“请求 owner 决策”或“提议完成”；平台调度器只校验成员、限额和安全策略，不替团队做业务决策 — 默认理由: 让自主接力可执行、可观察，也避免暗中引入中央管理 Agent
- A-5 2026-07-29 [生效] “完成”需至少一名非执行者 Agent 复核通过，或由 owner 明确终止；运行具备可配置的轮次/用量上限 — 默认理由: 防止单 Agent 自说自话完成和失控循环
- A-6 2026-07-29 [生效] 文件工具被限制在项目绑定根目录内；命令采用受控执行并记录输入、输出与退出码，越界、破坏性和外部副作用动作进入审批 — 默认理由: Agent 获得实际执行力时必须保留最低安全边界和审计链
- A-7 2026-07-29 [生效] 首版界面与内置文案使用简体中文，桌面浏览器优先并兼顾基础响应式布局 — 默认理由: 当前需求语言与本地使用场景均指向中文桌面端
- A-8 2026-07-29 [生效] 仅借鉴 Clowder AI 的产品原则与信息架构，不复制其品牌、猫角色、商标或视觉资产，也不直接移植其实现代码 — 默认理由: 保持产品边界清晰并规避品牌与实现耦合
- A-9 2026-07-29 [生效] 首版技能是可复用、可版本化并分配给 Agent 的文本指令包，不包含任意代码执行或远程市场安装 — 默认理由: 先验证角色能力组合，避免把插件供应链安全引入 MVP
- A-10 2026-07-29 [生效] 使命看板是子任务、依赖、负责人和状态的唯一事实源；Agent 可提出或执行合法状态变更，平台以确定性规则校验 — 默认理由: 自治协作仍需要机器可判定的项目状态，不能只依赖聊天叙述
- A-11 2026-07-29 [生效] 共享记忆只收录带来源的结构化条目（目标、决策、事实、产物、经验），原始聊天不会无筛选地自动变成长久记忆 — 默认理由: 降低错误沉淀与上下文无限膨胀
- A-12 2026-07-29 [生效] 首版最多同时运行两个独立子任务；每个并行任务先产出隔离草稿或变更集，共享文件冲突必须串行整合并留痕 — 默认理由: 提供真实并行价值，同时控制资源消耗和并发写入风险
- A-13 2026-07-29 [生效] owner 的新消息、@Agent 或暂停指令优先于后续 Agent 调度；正在执行的原子工具动作安全结束后，团队按 owner 最新方向继续 — 默认理由: owner 是项目方向的最终裁决者，但不应通过强杀进程破坏工作区
- A-14 2026-07-29 [生效] Agent 的稳定角色身份与底层 provider/model 绑定分离，更换模型不丢失其项目成员身份、技能和协作历史 — 默认理由: 持久身份是参考设计中最值得保留的核心能力
- A-15 2026-07-29 [生效] 并行运行引用的目标、决策或依赖发生变化时，旧结果标记为过期且不能自动推动后续接力 — 默认理由: 基于失效上下文继续自治比普通执行失败更危险
- A-16 2026-07-29 [生效] UI 展示消息、结构化状态、工具动作、用量、产物和证据，不保存或展示模型隐藏思维链 — 默认理由: 协作透明应建立在可审计事件而非私密推理文本上
- A-17 2026-07-29 [生效] 协作驾驶舱以桌面三栏为主，窄屏把右侧上下文收进可切换抽屉，移动端首版只保证查看、发言和审批 — 默认理由: 复杂协作需要并列上下文，目标用户的主要创作场景是桌面端
- A-18 2026-07-29 [生效] 首版先交付浅色主题：温暖中性色作为底色，每名 Agent 使用一枚克制的专属强调色；不使用无意义紫色渐变、玻璃拟态或多套阴影 — 默认理由: 营造陪伴感同时保持长时间工作的可读性
- A-19 2026-07-29 [生效] Agent 头像首版使用可上传图片或自动生成的文字/几何占位，不使用 emoji 或仿 Clowder 猫角色；图标统一来自同一图标库 — 默认理由: 提供身份辨识度，同时避免廉价占位和品牌模仿
- A-20 2026-07-29 [生效] Provider API key 必须以本机独立主密钥加密后持久化，保存后任何 API 与 UI 只返回掩码提示，密钥及明文不得进入日志 — 默认理由: S-2 要求配置持久化，明文写入 SQLite 会制造不必要的凭据泄露风险
- A-21 2026-07-29 [生效] S-2 的 Agent 头像先交付文字/几何头像与可选强调色，不实现图片上传；图片头像可在真实反馈证明需要后追加 — 默认理由: 当前演示判据只要求角色可辨识，文件上传不是组队闭环的必要条件
- A-22 2026-07-29 [生效] OpenAI-compatible 连接验证只接受 http/https URL，禁止 URL 内嵌凭据并设置有限超时；非 HTTPS 地址必须由 owner 明确确认后才保存 — 默认理由: 兼容本地模型服务的同时避免静默接受明显不安全的远程配置
- A-23 2026-07-29 [生效] Provider 主密钥必须与 SQLite、源码、日志和 API 响应分离；仅拿到数据库不能解密凭据，主密钥缺失或无法安全创建时保存必须失败关闭且不得落盘 API key — 默认理由: “数据库里不是明文”不足以证明凭据边界安全
- A-24 2026-07-29 [生效] Provider 验证请求不跟随重定向并在 10 秒内超时，任何 3xx 都视为失败且不得把 Authorization 转发到新地址 — 默认理由: 防止 owner 配置的 endpoint 通过重定向把凭据带往另一主机，同时避免配置界面无限等待
- A-25 2026-07-29 [生效] 持久文本采用保守上限：名称 80、职责 160、说明 280、URL 2048、模型标识 120、API key 8192、技能/系统提示正文 20000 个字符；头像文字 1–4 个 Unicode 字符；单次 token 预算为 1–1000000 的整数、接力轮次为 1–100 的整数 — 默认理由: 阻止异常输入撑大本地数据库与 UI，同时覆盖常见模型标识、提示词和预算范围
- A-26 2026-07-29 [生效] Provider 模型目录响应最多读取 1 MiB 且最多接受 10000 个模型条目，超限按不兼容响应失败 — 默认理由: 连接验证只需确认一个模型标识，不应让用户配置的 endpoint 无界占用本地内存
- A-27 2026-07-29 [生效] 项目工作区必须是本机已存在、可读取的绝对目录，保存前解析为真实规范路径；S-3 只绑定和展示路径，不读取文件内容或运行命令 — 默认理由: 先建立明确边界，实际工具访问留到 S-5 单独验收
- A-28 2026-07-29 [生效] 同一个规范工作区同一时间只绑定一个项目，改绑需 owner 明确确认；禁止用相对路径、文件路径或不存在目录占位 — 默认理由: 避免后续多个自治项目同时改写同一目录
- A-29 2026-07-29 [生效] 项目成员关系不记录 leader/rank，所有 Agent 具有相同协作地位；职责和工具权限来自 Agent 自身配置，不等于组织层级 — 默认理由: 落实用户要求的群组内平等协作
- A-30 2026-07-29 [生效] S-3 的使命看板由 owner 手工建立目标与子任务，自动拆解与领取从 S-4 开始；任务状态由确定性规则维护，不从聊天文本猜测 — 默认理由: 先验证共享项目上下文和事实源，再引入模型自治
- A-31 2026-07-29 [生效] 共享记忆仅包含目标、决策、事实、产物四类显式条目，每条必须有来源类型、来源引用和创建者；S-3 由 owner 写入，Agent 只通过相同项目上下文快照读取 — 默认理由: 防止原始聊天或无来源结论静默进入长期记忆
- A-32 2026-07-29 [生效] 项目组至少包含 2 名 Agent，不设置产品层硬上限；同一 Agent 在项目内只能有一个成员关系且不设 leader — 默认理由: 两名成员是协作与后续接力的最小闭环，额外上限应由真实资源反馈决定
- A-33 2026-07-29 [生效] 使命标题最多 80、目标 5000、子任务标题 160、说明 5000、记忆正文 20000、来源引用 2048 个字符；超限明确拒绝 — 默认理由: 保持项目上下文可读并阻止异常文本无界撑大数据库
- A-34 2026-07-29 [生效] 看板状态固定为待办、进行中、阻塞、完成；依赖必须同属一个使命且禁止自依赖和环路，状态变更采用 optimistic version 冲突保护 — 默认理由: 使命看板是机器事实源，必须有确定性状态和可验证依赖
- A-35 2026-07-29 [生效] 自动化 demo 使用独立进程中的本地 OpenAI-compatible 测试 provider 执行真实 HTTP chat-completions 协议；产品运行时与外部 provider 走同一路径，不把 fixture 输出写死在 Agent 实现中 — 默认理由: 仓库不能携带用户云端凭据，但仍需验证真实网络、凭据解密、请求和响应解析边界
- A-36 2026-07-29 [生效] S-4 采用单持棒者顺序接力，同一协作运行任一时刻只有一名 Agent 生成或提交动作；独立子任务并行从 S-5 开始 — 默认理由: 先验证平等接力、暂停和恢复，再引入并行冲突面
- A-37 2026-07-29 [生效] Agent 每轮只提交受 schema 约束的消息、任务提案、领取、交棒、决策请求或完成动作；平台不保存/展示隐藏思维链，结构解析失败只允许一次不计业务轮次的格式修复请求 — 默认理由: 审计应基于明确动作，不依赖私密推理文本
- A-38 2026-07-29 [生效] owner 的新消息优先于待继续的自治轮次；显式 @Agent 把下一棒定向给该成员，未 @ 时由当前持棒者结构化交棒，系统不设固定协调者 — 默认理由: owner 必须能随时介入，同时保持 Agent 平等
- A-39 2026-07-29 [生效] S-4 每次运行最多 50 个业务轮次，并逐 Agent 执行其 maxTokens 与 maxHandoffs 配置；达到边界即暂停并说明，不静默追加调用 — 默认理由: 防止异常模型响应形成无限接力或不可审计消耗
- A-40 2026-07-29 [生效] 决策请求包含一个问题和 2–8 个明确选项，也允许 owner 自由文本回答；等待回答时运行持久化暂停，重启后可继续 — 默认理由: 将真正需要 owner 裁决的分歧显式化，而不是让 Agent 猜测
- A-41 2026-07-29 [生效] 协作 turn 的持久 lease 为 120 秒；调用中断或 lease 过期只允许 owner/客户端显式重试，新 attempt 可再次调用 provider 但同一 attempt 的状态动作最多提交一次 — 默认理由: 本地 Next 进程没有常驻队列，必须能从崩溃中恢复又不能重复写任务/交棒
- A-42 2026-07-29 [生效] 单轮 owner/Agent 可见消息最多 10000/20000 字符，模型每轮最多提议 20 个子任务；任务字段沿用 S-3 边界，交棒摘要最多 5000，决策问题最多 1000 字符 — 默认理由: 控制 prompt、时间线和结构动作的最坏体积
- A-43 2026-07-29 [生效] S-4 要求 provider 返回非负整数 usage；缺失或不一致时不伪造 token 数，当前 turn 失败并暂停等待 owner 重试或更换 provider — 默认理由: owner 要看到可信用量，预算不能建立在猜测上
- A-44 2026-07-29 [生效] 模型 prompt 始终包含完整当前使命/看板/active 记忆，但公开聊天时间线只带最近 30 条且最多 60000 字符；更早内容仍完整保留在审计时间线，不静默写入摘要 — 默认理由: 在尚未引入可信摘要机制前给 prompt 一个确定上界，同时不伪造丢失历史
- A-45 2026-07-29 [生效] chat-completions 响应最多读取 1 MiB；超限视为 provider 响应无效并暂停，原始响应不落盘 — 默认理由: Agent 可见消息和结构动作已有更小边界，不应允许外部 endpoint 无界占用内存
- A-46 2026-07-30 [生效] S-5 同一项目最多并行两个 execution，且只能调度依赖已完成、已领取、状态为进行中的不同任务；同一任务任一时刻最多一个 active execution — 默认理由: 延续 A-12 的资源上限，并以看板 DAG 作为可机械判定的并行边界

- A-48 2026-07-30 [生效] S-5 只开放结构化的目录列举、文本文件读取/写入和进程执行工具；路径解析 realpath 后必须位于 sandbox，拒绝符号链接逃逸、设备路径、二进制/超限文件与任意 shell 字符串 — 默认理由: workspace_guarded 要求工具边界可审计且默认失败关闭

- A-51 2026-07-30 [生效] execution 捕获任务、依赖、项目上下文和 workspace 文件基线 hash；任一相关事实或文件在提交前变化，结果标记 stale，usage/工具审计保留但不得推进任务或接力 — 默认理由: 落实 A-15，旧上下文产物不能因为模型调用成功就自动进入主工作区
- A-52 2026-07-30 [生效] 工具调用与进程输出分别设置数量、文本体积、运行时间和总执行轮次上限；进程超时先终止进程树，无法确认终止时 execution 失败关闭且不合入 — 默认理由: 本地自治执行必须有确定资源边界和可恢复终态
