## 0. 第一性原理

Cool AI 的定义：单一 owner 把平等角色 Agent 组成项目组，围绕打开的本机文件夹公开协作并交付可追溯成果。

阶段 1（P1）只证明三件事：

1. **有工作对象**：用操作系统文件夹选择器打开文件夹，进入或恢复 Project（不手输路径）。
2. **有作业班组**：系统提供规划 / 实施 / 复核三名自带 Agent（模板落地为真实 Agent）。
3. **有公开作业面**：中间是会话与 composer；工具结果在对话流中，而不是四个常驻治理面板。

交互参考（只取信息架构，不拷贝资产）：pi 与 DeepSeek Harness 的 session + chat；`Choose workspace` 走宿主原生目录选择器。

## 1. 开发步骤规则（每个特性都遵守）

1. **一个特性 = 一个主用户结果**：不把多个独立能力打包成一个切片。
2. **后端 API 契约先行**：先定义并落盘路由、严格 DTO、schema（如涉及）、错误语义与失败关闭行为，配套领域测试。
3. **前端消费 API**：提供对应交互与展示，覆盖 loading / empty / error / disabled / success / focus 全态，控件 ≥44px，关键界面过 axe。
4. **验收闭环**：聚焦测试 → `tsc` → `build` → 真实渲染/浏览器冒烟 → 记录演示验收。
5. **纯 UI / 视觉收敛切片**（如 P0）只消费既有 API 或纯壳层，不新增领域事实；不得为了视觉改动伪造数据。
6. **先闭环、再变厚**：任何新功能先落到基本可用的主路径，再叠加整理、治理与扩展能力。

**目标**：一次做对视觉与信息架构，并把开发步骤规则固化；治理面从主路径卸载。

**切片与前后端拆分**：

| 内容 | 前端 | 后端 |

| 壳层二：240px 会话侧栏 | 「对话」标题、+ 新对话、过滤 tabs（全部/收藏/标签）、线程列表、回收站 | 无 |

## 5. P2 — 会话基础

**目标**：把执行、审批、审计与任务事实在对话流/按需视图中可见、可追溯，执行者不能独自宣布完成。

**切片与前后端拆分**：

| 切片 | 前端 | 后端 |
|---|---|---|
| 005 安全并行执行 | 执行/审批/冲突/验证在对话流展示 | 隔离执行、sandbox、merge、审批 |
| 027 工作区只读浏览 | 文件树、文本/资产预览 | verified browse、越界拒绝 |
| 029 统一审批中心 | 审批入口、来源/影响展示 | 跨域审批、过期失败关闭 |
| 028/030/035m/036/037/041 审计纵切 | 统一审计中心、按域筛选、来源导航 | outbox/checkpoint/rebuild、脱敏事件 |
| 047 运行时间轴 | 时间轴展示 | 只读运行投影 |
| 026 依赖洞察 | 依赖图、阻塞原因、节点定位 | 依赖查询、环检测 |
| 043 SOP 状态 / 044 派发租约 | 流程状态、派发控制展示 | 状态投影、租约与派发 |

## 8. P5 — 知识与扩展

**目标**：把目标、决定、事实、产物组织为可检索、可取代、可复核的项目知识，并接入受控扩展。

**切片与前后端拆分**：

| 切片 | 前端 | 后端 |
|---|---|---|
| 045 记忆检索 | 检索框与结果展示 | 记忆检索服务 |
| 046 能力画像 | 画像与路由建议展示 | 画像查询、规则建议 |
| 048 浏览器通知/PWA | 通知权限、通知 UI | 订阅管理与推送 |
| 扩展（MCP/CLI/语音等，边界外） | 按受控端口独立切片 | 不改变核心事实与安全协议 |

**验收**：检索结果带来源；能力画像可解释；通知最小权限。

## 9. 阶段与演进层的关系

- 演进层（[`product.md`](./product.md)）：核心协作 / 可信执行 / 知识治理 / 扩展运行时 = 能力累积。
- 本计划的 P0–P5 = 用户可感知的交付顺序，与演进层一致但按“先闭环、再变厚”重排。
- 已 ship 的切片是既有事实，不因本计划改写；新开发按本计划阶段推进，同一切片只对应一个主用户结果。Capability 与切片注册见 [`backlog.md`](./backlog.md)。
- 对历史切片：049 图标优先 + HelpTip 被 P1 取代，不 ship。050/S-60 为 P1 主切片；051/S-61 为 P0 主切片。使命/记忆/SOP/画像的 API 与领域测试保留，只从阶段 1 主路径卸载，收进图标轨按需打开。
